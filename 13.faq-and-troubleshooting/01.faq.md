# Frequently Asked Questions

## General

**Q: Is Tako a UI library or a framework?**
A: Tako is a comprehensive application framework. It does not draw pixels or text directly. Instead, it manages your application's architecture (IoC, Routing, State) and relies on UI Adapters (like Bubbletea) and styling libraries (like Lipgloss) to handle the actual rendering.

**Q: Can I use Tako to build headless CLI applications?**
A: Absolutely! Tako natively supports CLI commands. If a registered CLI command is executed, Tako instantly suppresses the UI layer and runs in Headless Mode, allowing you to use `fmt.Println` and standard logging without breaking the terminal.

## Architecture

**Q: Why does `app.Make(&service)` return an error?**
A: This usually happens because the service has not been bound to the IoC Container, or you are trying to resolve a concrete struct instead of an interface pointer. Always ensure you bind interfaces (`app.Singleton(new(MyInterface), &Impl{})`).

**Q: Where should I put my global variables?**
A: You shouldn't have any. Global variables are an architectural liability. Use the Context API's State Manager (`ctx.State().Mutate()`) for ephemeral runtime state, or the Storage Manager (`ctx.Storage().Put()`) for persistent data.

## Routing & UI

**Q: Why is my component not updating on the screen?**
A: Tako components are designed not to be reactive by default to save CPU cycles. If your component's internal struct changes, you must explicitly call `ctx.RenderNow()` to signal the UI Adapter that a redraw is required on the next frame tick.

**Q: Can I nest Layouts infinitely inside Layouts?**
A: Yes! You can chain `app.Router().Scope().Root().Scope().Root()`. The Router will recursively wrap your active component inside all parent layouts.

## Debugging

**Q: I can't see `fmt.Println` output when my TUI is actually running!**
A: This is because the UI Adapter (e.g., Bubbletea) takes full control of `stdout` to render the TUI. If you need to debug, use the `ctx.Logger().Info()` method. The logs are asynchronously written to `.tako/storage/logs/tako.log` without breaking your visual interface.
