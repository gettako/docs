Building complex TUI applications is difficult to debug. Because the UI Adapter takes complete control over your terminal screen, you cannot simply drop a `fmt.Println` to inspect state without breaking your UI and causing text to overlap.

Tako provides a suite of Developer Tools out of the box to solve this exact problem.

## The Tako Inspector

The Inspector is a built-in CLI tool that connects to your currently running Tako application via the **RPC Bus** and streams live debugging data to a completely separate terminal window.

### 1. Enabling the Inspector Daemon
First, ensure that your application starts the RPC server during boot. If you are using `tako.NewApp()`, this is handled automatically for you in Dev Mode.

### 2. Launching the Inspector
Open a *second* terminal window, navigate to your project directory, and run the built-in inspector command:

```bash
go run main.go inspect
```

If your primary application is running, the Inspector will connect to the `.tako/run/*.sock` file and open a live debugging dashboard.

## Inspector Features

Once connected, the Inspector provides several tabs that provide visibility into your app:

- **Metrics:** A live, real-time view of the application's memory usage, active goroutine count, and CPU utilization.
- **Router:** A live trace of your routing history, showing which middlewares passed or failed, and the current active layout hierarchy.
- **State:** Real-time visibility into the global State Manager. You can see exactly what keys exist in memory and their current, dynamically changing values.
- **Events:** A live stream of every event dispatched across the Event Bus, complete with deep payload inspection.

## The Profiler Manager

If you need to dig deeper into performance bottlenecks, Tako includes a `contracts.ProfilerManager`. This manager wraps Go's native `pprof` package.

You can trigger a CPU or Memory profile directly via the Context API:

```go
func HandleHeavyTask(ctx contracts.Context) {
    // Start recording a CPU profile
    ctx.Profiler().StartCPUProfile()
    
    // Do heavy work...
    ProcessGigabytesOfData()
    
    // Stop recording and save to .tako/storage/profiles/
    ctx.Profiler().StopCPUProfile()
}
```

You can then analyze the generated profile using the standard Go toolchain:
```bash
go tool pprof .tako/storage/profiles/cpu.prof
```

## Seamless Logging

As emphasized in the core services documentation, always use `ctx.Logger().Info()` instead of `fmt.Println`. Tako's logger writes rolling logs directly to `.tako/storage/logs/tako.log`. You can easily tail this log in a separate terminal to watch background processes safely:

```bash
tail -f .tako/storage/logs/tako.log
```

By leveraging the Inspector, the Profiler, and the Logger, you can understand, profile, and debug your application's behavior without compromising the primary TUI experience.
