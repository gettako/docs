The `ThemeManager` uses semantic color tokens — abstract names like `primary`, `success`, and `surface` — rather than hardcoded hex values. Providers ask for a semantic role; the
manager resolves it against the active palette. When the theme changes, an event fires and all UI components redraw with the new colors.

## Registering Palettes

A palette maps token names to ANSI strings or hex codes:

```go [themes/dracula.go]
func RegisterDracula(app tako.Application) {
    app.ThemeManager().Register("dracula", map[string]string{
        "primary":    "#bd93f9",
        "secondary":  "#6272a4",
        "success":    "#50fa7b",
        "warning":    "#f1fa8c",
        "error":      "#ff5555",
        "info":       "#8be9fd",
        "surface":    "#282a36",
        "background": "#1e1f29",
        "foreground": "#f8f8f2",
        "muted":      "#44475a",
        "border":     "#6272a4",
    })
}
```

::tip
Always stick to a standard token set across all your themes. The list above is a solid baseline for any TUI application.
::

## Using Tokens in Render

When rendering, ask the theme manager for the active color value:

```go [providers/status/provider.go]
func (p *StatusProvider) Render(ctx *tako.Context) string {
    theme := ctx.ThemeManager()

    indicatorColor := theme.Get("success")
    if p.hasErrors {
        indicatorColor = theme.Get("error")
    }

    return lipgloss.NewStyle().
        Background(lipgloss.Color(theme.Get("surface"))).
        Foreground(lipgloss.Color(indicatorColor)).
        BorderForeground(lipgloss.Color(theme.Get("border"))).
        Padding(0, 1).
        Render(p.statusText)
}
```

If a token isn't found in the active palette, `Get()` returns `""` (terminal default).

## Runtime Theme Switching

Activate a theme using `Use()`:

```go [commands/theme.go]
func (c *ThemeCommand) Execute(ctx *cli.Context, args []string) error {
    themeName := args[0]
    if err := ctx.App().ThemeManager().Use(themeName); err != nil {
        return fmt.Errorf("unknown theme: %s", themeName)
    }
    return nil
}
```

This updates the active palette and emits a `"theme:changed"` event on the bus.

## Caching Styles

Calling `lipgloss.NewStyle()` on every render frame is expensive. Cache your styles during `OnActivate` and rebuild them only when the theme changes:

```go [providers/editor/provider.go]
type EditorProvider struct {
    styles EditorStyles
}

type EditorStyles struct {
    LineNumber lipgloss.Style
    ActiveLine lipgloss.Style
    Keyword    lipgloss.Style
}

func (p *EditorProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    // Build initial styles
    p.rebuildStyles(ctx.ThemeManager())

    // Rebuild when theme changes
    ctx.Subscribe(ctx.Context, "theme:changed", func(e contracts.Event) {
        p.rebuildStyles(ctx.ThemeManager())
    })
    return nil
}

func (p *EditorProvider) rebuildStyles(theme tako.ThemeManager) {
    p.styles.LineNumber = lipgloss.NewStyle().Foreground(lipgloss.Color(theme.Get("muted")))
    p.styles.ActiveLine = lipgloss.NewStyle().Background(lipgloss.Color(theme.Get("surface")))
    p.styles.Keyword = lipgloss.NewStyle().Foreground(lipgloss.Color(theme.Get("primary"))).Bold(true)
}
```

::tip
If your application supports arbitrary user-provided themes, validate that every required token exists before accepting the theme. Fall back to your default theme's values for any
tokens the user forgot to specify, so the UI doesn't break due to missing colors.
::
