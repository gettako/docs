In a TUI application, stdout belongs to the renderer — writing to it directly corrupts the display. Tako's logger redirects all output to `.tako/logs/tako.log` as structured JSON.
Use `ctx.Logger()` in providers; `app.Logger()` during bootstrap before the context is available.

## Interface

```go [contracts/logger.go]
type Logger interface {
    Debug(msg string, args ...any)
    Info(msg string, args ...any)
    Warn(msg string, args ...any)
    Error(msg string, args ...any)

    // Returns a child logger with pre-attached key-value pairs.
    With(args ...any) Logger

    // Returns a child logger that namespaces all keys under group.
    WithGroup(name string) Logger
}
```

## Usage

```go [providers/orders/provider.go]
func (p *OrderProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    start := time.Now()

    orders, err := p.api.FetchActive(ctx.Context)
    if err != nil {
        ctx.Logger().Error("failed to fetch active orders",
            "err", err.Error(),
            "duration_ms", time.Since(start).Milliseconds(),
        )
        return err
    }

    ctx.Logger().Info("orders loaded",
        "count",    len(orders),
        "duration_ms", time.Since(start).Milliseconds(),
    )
    ctx.State().Set("orders:active", orders)
    return nil
}
```

Log levels guide:

| Level   | Use For                                                           |
|---------|-------------------------------------------------------------------|
| `Debug` | Verbose dev/troubleshooting info — cache hits, loop iterations    |
| `Info`  | Normal operation milestones — provider initialized, data loaded   |
| `Warn`  | Unexpected but handled situations — retry, degraded mode          |
| `Error` | Operation failures that don't crash — API failure, file not found |

::tip
For unrecoverable errors, log with `Error` and return the error to the caller. The application's panic recovery handler in the TUI kernel will log the panic and restore the
terminal before the process exits.
::

## Key-Value Pairs

Pass alternating key-value pairs for structured context:

```go [providers/sync/provider.go]
ctx.Logger().Info("sync completed",
    "items_synced", syncedCount,
    "errors",       errorCount,
    "duration_ms",  elapsed.Milliseconds(),
    "endpoint",     p.apiEndpoint,
)
```

Keys must be strings. Values can be any type — they're serialized via `fmt.Sprintf` or JSON encoding. Structured pairs make logs grep-able and parseable by log aggregators.

## Contextual Logger (`With` & `WithGroup`)

In highly-concurrent applications, logs from different goroutines or providers can be hard to correlate. Use `With` to create a **child logger** that permanently attaches key-value
pairs to every subsequent log entry — without repeating them on each call.

```go [providers/sync/provider.go]
func (p *SyncProvider) Boot(app *foundation.Application) error {
    // Create a child logger scoped to this provider.
    // Every log call on `log` will automatically include provider=sync.
    log := app.Context().Logger().With("provider", "sync")

    log.Info("starting sync")                                    // provider=sync
    log.Error("sync failed", "err", err.Error())                 // provider=sync err=...
    return nil
}
```

You can chain `With` calls to progressively narrow context:

```go
baseLog := ctx.Logger().With("provider", "network")

// Inside a background job:
jobLog := baseLog.With("job", "fetch-orders", "attempt", retryCount)
jobLog.Info("job started")
jobLog.Error("job failed", "err", err.Error())
```

Use `WithGroup` to **namespace** all subsequent key-value pairs under a sub-object in the JSON output, which is useful when you want to group related attributes:

```go
// Keys are namespaced: db.duration_ms, db.rows_affected
dbLog := ctx.Logger().WithGroup("db")
dbLog.Info("query executed", "duration_ms", 12, "rows_affected", 100)
```

Resulting JSON output:

```json
{"time":"2025-06-12T08:12:30Z","level":"INFO","msg":"query executed","db":{"duration_ms":12,"rows_affected":100}}
```

::tip
Child loggers created by `With` and `WithGroup` share the underlying file handle with the parent — they are lightweight wrappers. Only the root logger (created in `bootstrap`) owns
the file handle and needs to be closed on shutdown.
::

## Log File Location

```
.tako/logs/tako.log
```

```json [.tako/logs/tako.log]
{"time":"2025-06-12T08:12:30Z","level":"INFO","msg":"orders loaded","count":42,"duration_ms":234}
{"time":"2025-06-12T08:12:31Z","level":"ERROR","msg":"failed to fetch notifications","err":"connection refused"}
```

::tip
During development, keep a second terminal open with `tail -f .tako/logs/tako.log | jq .` to watch logs in real-time with JSON pretty-printing.
::

## Built-In Log Viewer

Tako ships a TUI log browser:

```bash [terminal]
go run . log:view
```

Features: live streaming, severity filtering, full-text search, timestamp navigation, color-coded levels. Use it to debug background job failures or trace provider initialization
issues without leaving the terminal.

## Lifecycle Example

```go [providers/inventory/provider.go]
func (p *InventoryProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    p.app = app
    ctx.Logger().Info("inventory provider initializing",
        "sku_count", len(p.catalog),
    )
    return nil
}

func (p *InventoryProvider) Shutdown() error {
    ctx := p.app.Context()
    ctx.Logger().Info("inventory provider shutting down",
        "orders_processed", p.ordersProcessed,
    )
    return nil
}
```

::tip
Add a `"provider"` key as the first key-value pair in all your log calls — `ctx.Logger().Info("msg", "provider", "inventory", ...)`. This makes filtering by provider trivial (
`grep '"provider":"inventory"' tako.log`). It also makes the built-in log viewer's filter much more useful when you have 10+ providers all writing to the same log file.
::
