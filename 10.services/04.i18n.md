The `LangManager` provides dictionary-backed translations. Instead of hardcoding UI strings, you use dot-notated keys (e.g., `"nav.settings"`). The manager resolves these against
the active locale dictionary. When the locale changes, an event fires and the UI redraws immediately in the new language.

## File-Based Dictionaries (Auto-Loaded)

Tako automatically discovers and loads language files from `lang/` directories. This allows you to manage translations externally without recompiling your Go code.

The structure follows `lang/{locale}/{namespace}.yml`.

```yaml [lang/en/app.yml]
title: Tako Workspace
welcome: Welcome back, {}
```

```yaml [lang/en/nav.yml]
projects: Projects
settings: Settings
```

```yaml [lang/id/app.yml]
title: Ruang Kerja Tako
welcome: Selamat datang, {}
```

During bootstrap, Tako flattens these files. The file above becomes accessible as `app.title`, `app.welcome`, and `nav.projects`.

### Override Hierarchy

Just like configuration files, language dictionaries cascade. You can override specific keys in your user directory:

1. `[AppDir]/lang` (Base default translations)
2. `.tako/lang` (Development overrides)
3. `~/.my-app/lang` (Production overrides)

## Programmatic Registration

If you prefer to bundle translations into your binary or load them from a remote API, you can register them manually:

```go [providers/lang/provider.go]
func (p *LangProvider) Boot(app *foundation.Application) error {
    app.Context().LangManager().Register("en", map[string]string{
        "status.syncing": "Syncing :count files...",
        "action.save":    "Save",
    })
    return nil
}
```

## Translating Strings

Use the `T()` method to resolve a key:

```go [providers/dashboard/provider.go]
func (p *DashboardProvider) Render(ctx *tako.Context) string {
    lang := ctx.LangManager()

    // Simple lookup
    title := lang.T("app.title")

    // Lookup with formatting arguments (sequential)
    welcome := lang.T("app.welcome", p.userName)

    // Lookup with named parameters
    syncMsg := lang.T("status.syncing", map[string]any{
        "count": p.pendingFiles,
    })

    return fmt.Sprintf("%s\n\n%s\n%s", title, welcome, syncMsg)
}
```

The translation service supports both sequential placeholders (`{}`) and named parameters (`:key`). If you pass a `map[string]any` or `map[string]string` as the first argument, it
automatically uses named replacements.

If a key isn't found in the active dictionary, `T()` returns the literal key string (e.g., `"nav.projects"`), making missing translations obvious in the UI.

## Runtime Locale Switching

```go [commands/lang.go]
func (c *LangCommand) Execute(ctx *cli.Context, args []string) error {
    locale := args[0]
    if err := ctx.App().LangManager().SetLocale(locale); err != nil {
        return fmt.Errorf("unknown locale: %s", locale)
    }
    return nil
}
```

`SetLocale` switches the active dictionary and emits `"lang:changed"`.

## Caching Translations

If your provider computes expensive layouts based on string lengths, cache the translations in `Boot` and rebuild on locale changes:

```go [providers/sidebar/provider.go]
func (p *SidebarProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    p.rebuildMenu(ctx.LangManager())

    ctx.Subscribe(ctx.Context, "lang:changed", func(e contracts.Event) {
        p.rebuildMenu(ctx.LangManager())
    })
    return nil
}

func (p *SidebarProvider) rebuildMenu(lang tako.LangManager) {
    p.menuItems = []string{
        lang.T("nav.projects"),
        lang.T("nav.settings"),
        lang.T("nav.help"),
    }
    // Pre-calculate longest item for box sizing
    p.maxWidth = maxStringLength(p.menuItems)
}
```

::tip
Namespace your translation keys by provider name (`"editor.tab.close"`, `"filebrowser.action.delete"`) to avoid collisions between isolated providers.
::
