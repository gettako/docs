Every Tako application has a built-in CLI layer. When users run your binary without entering TUI mode (e.g., `app sync --timeout=30s`), they interact with commands. Use commands
for administrative tasks, data migration, cache clearing, and exposing features to shell scripts or CI/CD pipelines.

## The Command Interface

A command is a self-contained unit of work:

```go [contracts/command.go]
type Command interface {
    Name() string
    Description() string
    Execute(ctx *cli.Context, args []string) error
}
```

## A Complete Command

```go [commands/cache_clear.go]
package commands

import "gettako.dev/tako/cli"

type CacheClearCommand struct{}

// Name uses a colon to group related commands in help output
func (c *CacheClearCommand) Name() string {
    return "cache:clear"
}

func (c *CacheClearCommand) Description() string {
    return "Flush all application caches"
}

func (c *CacheClearCommand) Execute(ctx *cli.Context, args []string) error {
    // Access the service container
    store := ctx.App().Storage()

    if err := store.Delete("search_cache"); err != nil {
        return err // Returned errors are printed to stderr
    }

    // Write formatted output to stdout
    ctx.Writef("✓ Search cache cleared.\n")
    return nil
}
```

## Reading Flags

The `cli.Context` provides access to parsed flags:

```go [commands/sync.go]
func (c *SyncCommand) Execute(ctx *cli.Context, args []string) error {
    // String flag (returns "" if not set)
    endpoint := ctx.Flag("endpoint")
    if endpoint == "" {
        endpoint = "https://api.default.com"
    }

    // Boolean flag (returns true if present)
    dryRun := ctx.BoolFlag("dry-run")

    if dryRun {
        ctx.Writef("DRY RUN: Would sync to %s\n", endpoint)
        return nil
    }

    ctx.Writef("Syncing to %s...\n", endpoint)
    return p.performSync(endpoint)
}
```

Run it via: `myapp sync --endpoint=https://api.custom.com --dry-run`

## Registration

### Global Registration

Register commands in `main.go` before `app.Run()`:

```go [main.go]
func main() {
    app := tako.NewApp()

    app.Commands(
        &commands.CacheClearCommand{},
        &commands.SyncCommand{},
    )

    tako.Run(app)
}
```

### Provider Registration

Providers can register commands during their `Boot` phase. This allows providers to ship with their own administrative CLI tools:

```go [providers/auth/provider.go]
func (p *AuthProvider) Boot(app *foundation.Application) error {
    app.Commands(
        &commands.UserCreateCommand{},
        &commands.UserDeleteCommand{},
    )
    return nil
}
```

## Middleware

Wrap command execution with cross-cutting logic like timing or authentication:

```go [middleware/timing.go]
func TimingMiddleware(next cli.CommandFunc) cli.CommandFunc {
    return func(ctx *cli.Context, args []string) error {
        start := time.Now()
        err := next(ctx, args) // Execute the actual command
        ctx.Writef("\n⏱  Completed in %s\n", time.Since(start))
        return err
    }
}
```

Register middleware globally on the registry:

```go [main.go]
func main() {
    app := tako.NewApp()

    // Runs for every command, in the order registered
    app.Registry().Use(middleware.TimingMiddleware)

    app.Commands(&commands.SyncCommand{})
    tako.Run(app)
}
```

## Help Output and Namespaces

Commands named with colons (`cache:clear`, `cache:warm`) are automatically grouped visually in the help output:

```
$ myapp help

Available Commands:
  sync           Synchronise local data with remote API

 cache
  cache:clear    Flush all application caches
  cache:warm     Pre-populate caches
```

::tip
Design your application logic as services, and make both your CLI commands and TUI providers thin wrappers around those services. This ensures `myapp sync` and pressing `Ctrl+S` in
the TUI execute the exact same business logic without duplication.
::
