Tako provides commands that cover the development lifecycle — from scaffolding providers to inspecting runtime state. They're registered automatically and grouped into namespaces.

Run `myapp help` to see the full list.

## Core Commands

### `version`

Displays the application name, Go runtime version, and build metadata (commit hash, build time).

### `doctor`

Runs diagnostics on the environment. It checks the Go version, terminal capabilities (truecolor, sixel), configuration files, and provider dependencies. Perfect for debugging "
works on my machine" issues.

### `config:dump`

Outputs the resolved configuration map. Use `--key` to filter.
*Warning: This may expose sensitive values like API keys if printed to a log.*

## Introspection Commands

### `plugin:list`

Shows all registered plugins, their initialization order, boot time in milliseconds, and dependency graph.

### `route:list`

Lists all active keybindings, showing the key, the handler name, the zone scope, and priority. Use `--scope` to filter.

### `event:list`

Shows all registered event listeners and their subscriber counts.

### `hook:list`

Displays hook registrations, their providing provider, and their priority level.

## Scaffolding

Generate boilerplate code instantly. Use `--force` to overwrite existing files.

### `make:plugin <Name>`

Scaffolds a new plugin with a bootstrapper, lifecycle interface, and directory structure.

### `make:component <Name>`

Scaffolds a component. Pass `--mouse` to implement the `MouseComponent` interface.

### `make:command <Name>`

Scaffolds a CLI command with a `Signature()` method stub. Names like `db:migrate` are automatically supported.

## Development Tools

### `dev`

Starts the application with hot-reload enabled. Watches source files and debounces rebuilds automatically.

### `build`

Compiles a production-optimised binary with version data injected into the build flags.

### `inspect`

Launches the interactive debugger TUI for exploring the service container, event stream, and live state. (Requires the debugger provider).

### `replay`

Plays back recorded execution traces. Useful for time-travel debugging. (Requires the recorder provider).

### `status`

A terminal dashboard showing memory usage, goroutine counts, uptime, and event throughput.

## Disabling Built-in Commands

You can disable specific built-in commands (for leaner binaries or security) when constructing the app:

```go [main.go]
func main() {
    app := tako.NewApp(
        tako.WithoutCommands("inspect", "replay", "doctor"),
    )
    tako.Run(app)
}
```

`help` and `version` cannot be disabled.

::tip
If you build an internal tool that requires its own setup (e.g. database seeding, generating API clients), create custom commands in your own namespace (like `tool:setup` or
`api:generate`). The CLI is the perfect place for code that shouldn't run in the TUI but belongs in the same repository.
::
