Because Terminal User Interfaces (TUIs) take over the entire screen, you cannot use standard `fmt.Println()` to debug your application. Printing to `stdout` will break the terminal
layout!

Tako solves this by providing a robust, multi-channel logging system built on top of Go's native `log/slog` package and `Lumberjack` for automatic log rotation.

## The Default Logger

You can access the global logger from anywhere in your application by calling `app.Logger()`.

```go
func (p *AppProvider) Boot(app contracts.Application) {
	logger := app.Logger()

	logger.Info("Application has finished booting")
	logger.Debug("Loaded 5 configuration files")
	logger.Error("Failed to connect to database", "error", err)
}
```

The logger supports structured logging. You can pass key-value pairs at the end of the method call to attach contextual data to the log entry.

```go
logger.Info("User logged in", "user_id", 42, "ip", "192.168.1.1")
```

## Log Channels

By default, Tako writes logs to a file named `tako.log` inside your [Storage Directory](/getting-started/project-structure#storage-virtual-home).

However, you can define multiple "channels" to separate different types of logs. For example, you might want general application logs to go to `tako.log`, but security-related logs
to go to `security.log`.

You define channels in your `config/logging.yml` file:

```yaml [config/logging.yml]
default: "stack"

channels:
  stack:
    driver: "slog"
    path: "tako.log"
    level: "debug"
    
  security:
    driver: "slog"
    path: "security.log"
    level: "info"
```

To write to a specific channel in your code, use the `Channel()` method:

```go
app.Logger().Channel("security").Warning("Failed login attempt")
```

## Automatic Log Rotation

Tako automatically uses `lumberjack` under the hood to ensure your log files never grow out of control. When a log file reaches a certain size, it is archived, and a new file is
started.

You don't need to configure anything manually, but you can adjust the rotation thresholds in your `logging.yml` file.

## Extending (Custom Drivers)

Tako's Log Manager uses a powerful Driver-based architecture. If you don't want to use the default `slog` driver, you can easily write your own (for example, to stream logs
directly to Datadog, AWS CloudWatch, or a custom API).

### 1. Register the Driver

To register a custom driver, call the `Extend` method on the Log Manager. You typically do this inside the `Register` method of your `AppProvider`.

```go
import "gettako.dev/tako/contracts"

func (p *AppProvider) Register(app contracts.Application) {
	app.Logger().Extend("datadog", func(app contracts.Application, config map[string]any) contracts.Logger {
		// Instantiate and return your custom struct that implements contracts.Logger
		return &MyDatadogLogger{
			APIKey: config["api_key"].(string),
		}
	})
}
```

### 2. Configure the Channel

Once your driver is registered via `Extend`, you can use it in your `logging.yml` configuration file just like the built-in drivers:

```yaml [config/logging.yml]
channels:
  remote:
    driver: "datadog"
    api_key: "your-secret-api-key"
```

Now, any call to `app.Logger().Channel("remote").Info(...)` will automatically route through your custom driver!

## Graceful Shutdown

When your application shuts down (either via the user pressing `Ctrl+C` or calling a quit command), Tako automatically executes a graceful shutdown sequence.

During this sequence, the Logger guarantees that all open file handles (for every channel) are safely flushed and closed. You never have to worry about corrupted log files or
missing entries when the application exits.
