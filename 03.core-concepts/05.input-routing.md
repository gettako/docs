Tako solves input routing at scale using two core concepts: **Zones** and the **Focus Stack**.

## The Focus Stack & Zones

The **Focus Stack** represents the "depth" of your UI (e.g., modal layers):

```
Stack: ["base"]               ← normal app state
Stack: ["base", "search"]     ← search overlay is open
Stack: ["base", "search", "results"] ← results panel on top of search
```

Each stack level can have multiple **Zones**, but only one is considered "focused" at a time for keyboard input. 

**Routing Logic:**
1. Input is routed to the **topmost stack level** first.
2. For keys: It checks the currently focused zone at that level. If no match, it falls back to global keybindings.
3. For mouse: It checks all registered hitboxes at that stack level. If no match, the click is ignored.

## Keybindings

Tako provides fluent APIs to register keys either globally or scoped to a specific zone.

### Registering Keys

```go [lifecycle.go]
// 1. Global Binding (fires regardless of focus)
ctx.Keys().Bind("ctrl+f", func() {
    ctx.Overlay().ShowComponent(&SearchBox{})
})

// Alternative (Aliases)
ctx.Keys().Bind("ctrl+s|f2", func() { /* save */ })

// 2. Zone Binding (level 0 by default)
ctx.Keys().Zone("main").Bind("j", func() { /* scroll down */ })

// 3. Zone Binding at specific stack level
ctx.Keys().Zone("modal", 1).Bind("esc", func() { ctx.Overlay().Close() })
```

### Setting Focus

The router needs to know which zone is focused at each level:

```go [main.go]
app.Focus("main")                // focuses "main" at the current stack level
app.Router().Focus(1, "search")  // explicitly target the overlay level (if not using auto-routing)
```

### The Smart `ctrl+c`
Tako includes a smart `ctrl+c` behavior by default. If the stack has more than one level (i.e., a modal is open), `ctrl+c` is silently ignored, preventing accidental exits. Only at the root level does it trigger shutdown. You can override this globally or per-zone:

```go [main.go]
app.Keys().Bind("ctrl+c", func() { app.Shutdown() })
```

## Mouse Router & Drag-and-Drop

Because Tako is UI-agnostic, the framework doesn't know where elements are rendered. You must register **Hitboxes** every render cycle.

### Registering Hitboxes

Inside your `View()` function, declare where your zones are:

```go [layout.go]
// Call this every render cycle!
ctx.Mouse().UpdateHitbox("sidebar", x, y, width, height)

// Explicit stack level (e.g., overlay at level 1)
ctx.Mouse().UpdateHitboxAt(1, "modal-btn", btnX, btnY, w, h)
```

> **Memory Management:** When a layer is popped from the stack, all hitboxes and handlers for that level are automatically cleaned up.

### Registering Handlers

```go [lifecycle.go]
ctx.Mouse().Zone("sidebar").
    OnClick(func(x, y int) { ... }).
    OnRightClick(func(x, y int) { ... }).
    OnScrollUp(func(x, y int) { ... }).
    OnScrollDown(func(x, y int) { ... })
```

### Drag & Drop

Drag-and-drop is a seamless two-zone interaction:
1. The **source zone** registers `OnDragStart`.
2. The **target zone** registers `OnDrop`.

```go [lifecycle.go]
ctx.Mouse().Zone("file-list").
    OnDragStart(func(x, y int) {
        // track what is being dragged
    })

ctx.Mouse().Zone("trash-bin").
    OnDrop(func(fromZone string, x, y int) {
        if fromZone == "file-list" {
            // handle drop
        }
    })
```

## State Persistence

The focus stack state (which layers are open and which zones are focused) is automatically saved to the KV store on shutdown and restored on the next launch:

```go [kernel.go]
// Handled automatically by the TUI Kernel:
keyRouter.Stack().RestoreState(store)
keyRouter.Stack().SaveState(store)
```

This ensures that if the app is closed while a modal is open, the exact state is restored on the next launch.
