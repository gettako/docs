## State vs KV Store
- **State Manager (`ctx.State()`)**: In-memory, volatile, and highly reactive. Use this for runtime application state (e.g., active project, current tab, cursor position) that plugins need to react to immediately.
- **KV Store (`ctx.Storage()`)**: Persistent on disk, not reactive. Use this for saving user preferences, window sizes, or history that must survive restarts.

## Setting and Getting State

Any plugin can write or read from the shared state store.

```go [lifecycle.go]
// Plugin A: Sets the current active project
ctx.State().Set("project.active", "tako-framework")

// Plugin B: Reads the state
val := ctx.State().Get("project.active")
fmt.Println(val.(string))
```

## Watching for Changes

The real power of the State Manager is its reactivity. When `Set` is called, it automatically emits an event via the Event Bus (`contracts.EventStateChanged`). Plugins can `Watch` specific keys to react in real-time.

```go [lifecycle.go]
// Plugin C: A sidebar widget that displays the active project
unsubscribe := ctx.State().Watch(ctx, "project.active", func(newVal any) {
    // This callback is fired immediately when Plugin A calls Set()
    p.sidebarView.UpdateTitle(newVal.(string))
})

// Later, or in OnDeactivate:
unsubscribe()
```

The `Watch` method takes a `context.Context` as its first parameter and returns an unsubscribe function. If your component is destroyed, you should call it to prevent memory leaks.
