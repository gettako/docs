## State vs KV Store
- **State Manager (`ctx.State()`)**: In-memory, volatile, and highly reactive. Use this for runtime application state (e.g., active project, current tab, cursor position) that plugins need to react to immediately.
- **KV Store (`ctx.Storage()`)**: Persistent on disk, not reactive. Use this for saving user preferences, window sizes, or history that must survive restarts.

## Fluent API (Recommended)

Tako framework introduces a highly expressive **Fluent API** for interacting with the State Manager.

### Setting State (Producer)

Use `.Key()` to produce state updates. You can also specify an automatic expiration (TTL) for temporary states.

```go [producer.go]
// Basic broadcast
ctx.State().Key("project.active").Value("tako-framework").Broadcast()

// Broadcast with auto-expiration (TTL)
ctx.State().Key("notification.banner").
    Value("Saved successfully!").
    TTL(3 * time.Second). // Will be deleted automatically after 3s
    Broadcast()
```

### Watching for Changes (Observer)

Use `.Observe()` to listen for state mutations. It includes an integrated **Debounce** feature, which is incredibly useful for TUI applications to prevent excessive screen renders when state changes rapidly.

```go [observer.go]
unsubscribe := ctx.State().Observe("project.active").
    Debounce(100 * time.Millisecond). // Wait until data stops changing for 100ms
    OnUpdate(func(oldVal, newVal any) {
        fmt.Printf("Project changed from %v to %v\n", oldVal, newVal)
    }).
    Subscribe(ctx)

// To stop watching:
unsubscribe()
```

> [!NOTE]
> The legacy `.Set()` and `.Watch()` methods are still available for backward compatibility, but `.Observe()` is highly recommended as it prevents data race conditions with built-in Mutex locks and debounce functionality.
