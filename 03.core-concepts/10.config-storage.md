## Directory Architecture

Tako automatically determines the directory layout based on whether the app is running in **Development Mode** (via `go run`) or **Production Mode** (compiled binary).

### Development Mode (`go run main.go`)

Files are stored relative to the project root:

```text
my-project/
├── config/            ← GetConfigDir()
│   ├── app.yaml
│   └── database.json
├── data/              ← GetDataDir()
│   ├── logs/
│   │   └── tako.log
│   └── kv/
│       └── kv.db
└── .tako/             ← GetInternalDir() (gitignored)
    └── run/
        ├── tako.pid
        └── inspect.sock
```

### Production Mode (Compiled Binary)

Files are stored under `~/.app-name/` (binary name in kebab-case):

```text
~/.my-app/
├── config/            ← GetConfigDir()
│   ├── app.yaml
│   └── database.json
├── data/              ← GetDataDir()
│   ├── logs/
│   │   └── tako.log
│   └── kv/
│       └── kv.db
└── .internal/         ← GetInternalDir()
    └── run/
        ├── tako.pid
        └── inspect.sock
```

### How Build State Is Detected

```go
tako.IsDevelopmentMode() // true when:
// 1. TAKO_ENV=development is set, OR
// 2. The executable is running from the system temp directory (go run behavior)
```

## Configuration

Tako uses a **directory-based config loader**. Instead of a single file, Tako scans the entire `config/` directory for `*.yaml`, `*.yml`, and `*.json` files.

Each file's **basename** becomes the root prefix for its keys:

```yaml [config/app.yaml]
name: My App
debug: true
port: 8080
```

```json [config/database.json]
{
  "host": "localhost",
  "port": 3306,
  "name": "mydb"
}
```

These become accessible as:
- `app.name` → `"My App"`
- `app.debug` → `true`
- `database.host` → `"localhost"`
- `database.port` → `3306`

### Reading Config

Config is read-only. Plugins cannot write to config at runtime.

```go [plugin.go]
func (p *Plugin) OnInit(ctx *tako.Context) error {
    cfg := ctx.Config()

    debug := cfg.Bool("app.debug", false)
    name := cfg.String("app.name", "Default App Name")
    dbHost := cfg.String("database.host", "localhost")

    return nil
}
```

### Environment Variable Overrides

Any config key can be overridden with an environment variable using the `TAKO_` prefix. Dots are replaced by underscores:
- `app.debug` → `TAKO_APP_DEBUG=true`
- `database.host` → `TAKO_DATABASE_HOST=db.production.local`

### Auto-Scaffolding

If the `config/` directory does not exist when the application starts, Tako will automatically create it. No panic, no error — you get an empty config and can populate the directory later.

## KV Store

The KV Store is for **persistent plugin state** — data that should survive across sessions (e.g., last selected item, saved search history). It is stored at `data/kv/kv.db`.

### Using the KV Store

```go [plugin.go]
func (p *Plugin) OnInit(ctx *tako.Context) error {
    store := ctx.Storage()

    // Save a value
    store.Set("search.last_query", "golang")

    // Read it back
    var lastQuery string
    store.Get("search.last_query", &lastQuery)

    // Delete a key
    store.Delete("search.last_query")
    return nil
}
```

> **Namespacing:** Keys are global. Always prefix your keys with your plugin ID (e.g., `search.history` instead of just `history`) to avoid collisions.

### How It Works (Debouncing)

Writes to the store are **debounced**. Multiple rapid `Set` calls within a 500ms window are batched into a single disk write. The write uses an atomic rename (`write temp file → os.Rename`) to prevent corruption.

On app shutdown, the store guarantees a final synchronous flush to disk, ensuring data is never lost.
