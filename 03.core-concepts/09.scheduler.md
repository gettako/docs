## Dispatching One-off Jobs

To run a task without blocking the UI, use `Dispatch`. It provides a fluent API for handling success or error outcomes.

```go [lifecycle.go]
func (p *Plugin) handleDownload(ctx *tako.Context) {
    ctx.Jobs().Dispatch(func(workerCtx context.Context) (any, error) {
        // This runs in a background goroutine
        data, err := fetchLargeFile(workerCtx)
        return data, err
    }).OnSuccess(func(result any) {
        // Called when the job finishes successfully
        ctx.State().Set("download.status", "complete")
        ctx.Emit("ui:refresh", nil)
    }).OnError(func(err error) {
        // Called if the job returns an error
        ctx.State().Set("download.error", err.Error())
    })
}
```

## Scheduling Recurring Intervals

If you need to poll an API or update a clock, use `Every`. It returns a function that you can call to stop the interval.

```go [lifecycle.go]
func (p *Plugin) startPolling(ctx *tako.Context) {
    stopFunc := ctx.Jobs().Every(5 * time.Second, func() {
        // Runs every 5 seconds
        status := checkServerStatus()
        ctx.State().Set("server.status", status)
    })
    
    // Stop the polling when the plugin is destroyed
    ctx.OnDestroy(func() {
        stopFunc()
    })
}
```

## Relationship with `ctx.Spawn`

While `ctx.Jobs()` is great for discrete background tasks with success/error callbacks, `ctx.Spawn()` is a simpler alternative for firing off a background goroutine that is tracked by the framework but does not return a value via callbacks. Use `ctx.Jobs()` when you need structured results, and `ctx.Spawn()` for fire-and-forget loops.

## CancelAll and Error Propagation

You can call `ctx.Jobs().CancelAll()` to immediately cancel all running jobs. When an error is returned from a `Dispatch` job, it triggers the `OnError` callback. If no callback is registered, the error is quietly ignored.

## Graceful Cancellation

Tako's Job Scheduler is tied to the application's lifecycle. When `app.Shutdown()` is called, Tako will automatically signal the internal contexts to cancel and wait for all dispatched background jobs to finish gracefully before exiting.
