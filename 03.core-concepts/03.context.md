## What is `tako.Context`?

The `tako.Context` wraps the standard Go context and injects the **Service Container**. This allows any function that receives the context to instantly resolve framework services without relying on global variables.

Furthermore, it provides a massive array of **syntactic sugar** — helper methods that make common tasks (like binding keys, listening to events, or spawning goroutines) concise and fluent.

---

## Service Container Access

Instead of calling `container.Make()` manually for every core service, `tako.Context` provides cached, thread-safe accessors:

```go [plugin.go]
func (p *Plugin) OnInit(ctx *tako.Context) error {
    container := ctx.Container() // contracts.Container
    logger    := ctx.Logger()    // contracts.Logger
    config    := ctx.Config()    // contracts.Config
    storage   := ctx.Storage()   // contracts.KVStore
    hooks     := ctx.Hooks()     // hook.Registry
    bus       := ctx.Events()   // contracts.EventBus
    theme     := ctx.Theme()     // contracts.ThemeManager
    lang      := ctx.Lang()      // contracts.LangManager
    state     := ctx.State()     // contracts.StateManager
    jobs      := ctx.Jobs()      // contracts.Scheduler
    router    := ctx.Router()    // *router.Router
    overlay   := ctx.Overlay()   // contracts.OverlayManager
    
    return nil
}
```

These shortcuts resolve the service on the first call and cache it for subsequent accesses, ensuring maximum performance in hot paths like rendering loops.

## Event Bus Sugar

Publishing and subscribing to events is a common task, so `tako.Context` provides direct methods:

| Method                              | Equivalent to                              | Description                                |
|-------------------------------------|--------------------------------------------|--------------------------------------------|
| `ctx.Emit(event, data)`             | `ctx.Events().Publish(event, data)`      | Fires an event across the app.             |
| `ctx.Once(event, handler)`          | `ctx.Events().Once(ctx, event, handler)` | Listens for an event exactly once.         |
| `ctx.On(event, handler)`            | `ctx.Events().On(event, handler)`        | Listens indefinitely until cancelled.      |
| `ctx.Subscribe(sc, event, handler)` | `ctx.Events().Subscribe(sc, ...)`        | Listens, bound to a specific context `sc`. |

## UI and Router Sugar

When building views or handling interactions, `tako.Context` provides fluent builders for keys, mouse, and overlays:

### Keybindings (`ctx.Keys()`)

The `Keys()` builder lets you bind global or zone-specific keys instantly:

```go [plugin.go]
// Global binding
ctx.Keys().Bind("ctrl+f", func() { ... })

// Zone binding (level 0)
ctx.Keys().Zone("search-box").Bind("enter", func() { ... })

// Zone binding at specific stack level
ctx.Keys().Zone("modal-btn", 1).Bind("esc", func() { ... })
```

### Mouse Routing (`ctx.Mouse()`)

The `Mouse()` builder lets you update hitboxes and register click/drag handlers declaratively:

```go [plugin.go]
// Update hitbox (call inside View every frame)
ctx.Mouse().UpdateHitbox("list", x, y, width, height)

// Register interaction handlers
ctx.Mouse().Zone("list").OnClick(func(x, y int) { ... })
ctx.Mouse().Zone("list").OnDrop(func(from string, x, y int) { ... })
```

### Stack & Overlay Management

- **`ctx.Router()`**: Returns the Key Router, useful for low-level stack manipulation.
- **`ctx.Stack()`**: Shortcut for `ctx.Router().Stack()`.
- **`ctx.Overlay()`**: The main high-level API for overlays, components, and dialogs. Example: `ctx.Overlay().ShowComponent(myComponent)`.

## Lifecycle Management

Because a terminal application must shut down cleanly (restoring the screen state), background tasks must be tracked.

### `ctx.Spawn(func)`

If you need a background goroutine, **do not** use a raw `go func()`. Use `ctx.Spawn()`:

```go [plugin.go]
ctx.Spawn(func(c context.Context) {
    for {
        select {
        case <-c.Done():
            return // Shutdown requested
        case <-time.After(time.Second):
            ctx.Emit("clock:tick", time.Now())
        }
    }
})
```

The framework tracks all spawned goroutines using an internal `sync.WaitGroup` and guarantees it will wait for them to exit gracefully during application shutdown.

### `ctx.OnDestroy(func)`

Registers a synchronous callback that runs when the context is destroyed (typically during app teardown or plugin reload):

```go [plugin.go]
ctx.OnDestroy(func() {
    // Free resources, close files, stop internal timers
})
```

### `ctx.Derive()`

Creates a child context bound to the same container. Useful when you need an independently cancellable sub-context (e.g., for a sub-task that can time out without affecting the parent):

```go [plugin.go]
child, cancel := ctx.Derive()
defer cancel()

child.Spawn(func(c context.Context) {
    // This goroutine is cancelled when cancel() is called,
    // independently of the parent context's lifecycle.
})
```
