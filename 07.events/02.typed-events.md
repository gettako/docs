Raw event subscriptions require a type assertion on `e.Data` on every handler — and that assertion breaks silently at runtime when a refactor changes the payload type. Typed events
lift this contract to compile time: the Go compiler rejects wrong payload types at both the publish and subscribe sites.

## Defining a Typed Event

Create a shared `events` package containing your application's event contracts:

```go [events/order_events.go]
package events

import "gettako.dev/tako/event"

// OrderCompletedPayload defines the data contract for the "order:completed" topic.
type OrderCompletedPayload struct {
    OrderID    string
    CustomerID string
    Total      float64
    Items      []LineItem
}

// OrderCompleted is the canonical typed handle for this event.
// Import and use this from any provider — never hardcode the topic string.
var OrderCompleted = event.NewTypedEvent[OrderCompletedPayload]("order:completed")
```

::tip
Define typed events as exported package-level variables in a dedicated `events/` package. This creates a single source of truth for your event contracts — all providers import from
the same place.
::

## Emitting with Type Safety

```go [providers/checkout/provider.go]
import "myapp/events"

func (p *CheckoutProvider) completeOrder(ctx *tako.Context, order *Order) {
    // The compiler rejects any payload that isn't OrderCompletedPayload
    event.Emit(ctx.Events(), events.OrderCompleted, events.OrderCompletedPayload{
        OrderID:    order.ID,
        CustomerID: order.CustomerID,
        Total:      order.Total,
        Items:      order.Items,
    })
}
```

If a future refactor changes the payload type or renames a field, the compiler flags every publish site. No more grepping for all places an event is published.

## Subscribing with Type Safety

```go [providers/notifications/provider.go]
import "myapp/events"

func (p *NotificationProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()

    // Handler receives OrderCompletedPayload directly — no assertion needed
    event.Subscribe(ctx, events.OrderCompleted, func(payload events.OrderCompletedPayload) {
        p.showBadge(fmt.Sprintf("Order %s completed — $%.2f", payload.OrderID, payload.Total))
    })
    return nil
}
```

## Built-In Typed Events

The framework provides typed events for its own built-in topics:

```go [provider.go]
import "gettako.dev/tako/state"

func (p *Provider) Boot(app *foundation.Application) error {
    ctx := app.Context()

    // StateChanged delivers state.StateChange directly — no e.Data.(*StateChange) needed
    event.Subscribe(ctx, state.StateChanged, func(change state.StateChange) {
        if change.Key == "cart:items" {
            p.refreshCartWidget(change.NewValue.([]CartItem))
        }
    })

    // StateExpired for TTL/LRU eviction notifications
    event.Subscribe(ctx, state.StateExpired, func(expiry state.StateExpiry) {
        ctx.Logger().Debug("state key expired", "key", expiry.Key, "reason", expiry.Reason)
    })
    return nil
}
```

::note
Built-in typed events — `state.StateChanged`, `state.StateExpired`, `plugin.Activated` — are provided by their respective packages. Import and subscribe; don't redefine them.
::

## JSON Decoding for External Data

For events that arrive from external sources (WebSocket, IPC, HTTP), use `DecodeAndPublish` to parse and publish in one call with pooled reader allocation:

```go [providers/bridge/provider.go]
var NotificationReceived = event.NewTypedEvent[IncomingNotification]("notification:received")

func (p *BridgeProvider) onWebSocketMessage(ctx *tako.Context, raw []byte) {
    // Acquires a pooled bytes.Reader, decodes JSON into IncomingNotification,
    // publishes the typed event, then returns the reader to the pool.
    if err := event.DecodeAndPublish(ctx.Events(), NotificationReceived, raw); err != nil {
        ctx.Logger().Error("failed to decode notification", "err", err)
    }
}
```

Use this when bridging external data sources. It handles JSON deserialization, error recovery, and publication in one optimized call — zero reader allocation overhead.

## When to Use Typed vs Raw Events

| Use Typed Events When                          | Use Raw Events When                     |
|------------------------------------------------|-----------------------------------------|
| Multiple providers subscribe to the same event | Event carries no payload (pure signal)  |
| Payload has multiple fields                    | Event is internal to a single provider  |
| The event is part of a provider's public API   | Prototyping (shape still evolving)      |
| You want compile-time refactoring assistance   | Truly dynamic data (arbitrary metadata) |

```go [provider.go]
func (p *AppProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()

    // Typed — well-defined domain contract
    event.Subscribe(ctx, events.OrderCompleted, p.handleOrderCompleted)

    // Raw — zero-payload signal
    ctx.Subscribe(ctx.Context, "app:ready", func(e contracts.Event) {
        p.bootstrap()
    })
    return nil
}
```

::warning
Don't create `TypedEvent[struct{}]` for zero-payload signals. A raw `ctx.On("app:ready", ...)` is cleaner and carries the same information.
::

::tip
Keep your `events/` package lean — only payload types and typed event variables, no business logic. Providers import from `events/`, never from each other. This one rule makes your
provider dependency graph a clean tree: each provider imports core framework packages and the shared `events` package, nothing else.
::
