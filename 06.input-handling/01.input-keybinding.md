In a graphical web interface, users rely heavily on a mouse. In a Terminal User Interface (TUI), keyboard shortcuts are the core interaction mechanism.

Handling keystrokes in traditional TUI libraries often leads to building a large `switch` statement that tries to figure out what screen the user is on before executing an action.

Tako's Input Manager (`contracts.InputManager`) simplifies this by capturing keystrokes and routing them *only* to the components that are currently active on the screen.

## The `Keys` Method

Every UI component in Tako implements the `contracts.Component` interface, which mandates the `Keys(km KeyManager)` method. Tako automatically executes this method once when a component is mounted by the Router.

```go
type ServerList struct {
    // fields...
}

func (c *ServerList) Keys(km contracts.KeyManager) {
    // Bind a simple quit action
    km.Bind("q", func() {
        // Shutdown gracefully
    })

    // Bind navigation
    km.Bind("enter", func() {
        // Navigate
    })
}
```

## Global vs Local Keybindings

When you bind a key inside a component's `Keys()` method, that keybinding is **scoped locally** to the component. 
- It will **only** trigger if the component is currently active on the screen.
- When the user navigates away, Tako automatically unregisters the keybinding to prevent memory leaks and shortcut collisions.

### Global Keybindings
If you want a shortcut to be available everywhere (like pressing `ctrl+c` to quit at any time), register it globally during the Application boot phase inside a Service Provider.

```go
func (p *UIProvider) Boot(app contracts.Application) error {
    // Register global shortcuts directly on the Input Manager
    app.Input().BindGlobal("ctrl+c", func() {
        app.Shutdown()
    })

    return nil
}
```

## Advanced Keybinding Features

The Input Manager handles combinations and special keys mapped by the underlying UI Adapter, so you don't have to write low-level byte sequence parsers.

```go
func (c *EditorComponent) Keys(km contracts.KeyManager) {
    // Modifiers
    km.Bind("ctrl+s", c.saveFile)
    km.Bind("shift+tab", c.previousField)

    // Directional
    km.Bind("up", c.moveCursorUp)
    km.Bind("down", c.moveCursorDown)

    // Fallback / Catch-all
    km.OnFallback(func(key string) {
        // This fires for any key press not explicitly bound above.
        // It is useful for capturing text input fields.
        c.InsertText(key)
    })
}
```

## Auto-Render & Performance

By default, **every** keystroke that successfully matches a handler will automatically trigger a UI redraw (`RequestRender()`). This means you rarely need to call `ctx.RenderNow()` manually after pressing a button.

However, if your keybinding only performs background tasks (like logging, sending telemetry, or mutating non-visual state), you can skip the rendering phase to maximize CPU performance by chaining `.NoRender()`:

```go
func (c *Dashboard) Keys(km contracts.KeyManager) {
    // This handler will execute but will NOT trigger a visual redraw.
    km.Bind("ctrl+p", func() {
        // Send analytics payload
    }).NoRender()
}
```

## Annotating Keybindings with Descriptions

Every keybinding can carry a human-readable description using the `.Describe()` method. This description is surfaced via `GetBindings()` and enables you to auto-generate Help Panels or Cheatsheets without manual bookkeeping.

```go
func (c *ServerList) Keys(km contracts.KeyManager) {
    km.Bind("ctrl+c", func() { app.Shutdown() }).Describe("Quit application")
    km.Bind("ctrl+r", c.Refresh).Describe("Refresh server list")

    // Describe and NoRender can be chained in any order
    km.Bind("ctrl+p", c.sendTelemetry).Describe("Send telemetry").NoRender()
}
```

To render a help panel, simply call `GetBindings()`:

```go
for _, b := range ctx.Input().Keys().GetBindings() {
    fmt.Printf("%-12s %s\n", b.Key, b.Description)
}
```

## Key Normalization & Compatibility

The Input Manager automatically normalizes key strings to a canonical format, ensuring consistent behavior across different terminal adapters and key formats:

| Input Format    | Canonical Form |
|-----------------|----------------|
| `"c-c"`         | `"ctrl+c"`     |
| `"m-x"`         | `"alt+x"`      |
| `"<enter>"`     | `"enter"`      |
| `"<space>"`     | `" "`          |
| `"<esc>"`       | `"escape"`     |
| `"<tab>"`       | `"tab"`        |
| `"<up/down/left/right>"` | `"up"` / `"down"` / `"left"` / `"right"` |

This means bindings like `km.Bind("<enter>", fn)` and `km.Bind("enter", fn)` are identical.
