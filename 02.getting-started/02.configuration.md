Tako loads YAML and JSON files from a `config/` directory, flattens them into dot-notation keys, and exposes them through a simple typed API. Each file's basename becomes the root
prefix for all keys inside it.

## Configuration Directory

```
config/
├── app.yaml        # Keys: app.name, app.version, app.api.base_url, ...
├── database.yaml   # Keys: database.dsn, database.pool_size, ...
└── features.yaml   # Keys: features.dark_mode, features.beta_search, ...
```

The `config/` directory is created automatically on first run if it doesn't exist. An empty directory is valid — your application boots with no file-based config and falls back to
defaults.

## Defining Configuration Values

```yaml [config/app.yaml]
name: "Inventory Manager"
version: "2.1.0"
debug: false

api:
  base_url: "https://api.warehouse.io"
  timeout: 30
  retry_count: 3

ui:
  theme: "dracula"
  show_footer: true
```

Nested keys are accessed with dot notation, prefixed by the filename. The `api.base_url` key in `app.yaml` becomes `app.api.base_url` in code.

JSON is also supported — both formats produce the same flattened key structure and can be mixed freely:

```json [config/database.json]
{
  "dsn": "sqlite3://.tako/data/app.db",
  "pool_size": 5,
  "max_idle": 2
}
```

## Configuration Hierarchy (Cascading)

Tako uses a flexible 4-layer cascading configuration system. This allows you to define sensible defaults in your codebase while safely overriding them for local development or
production environments, without duplicating entire files or using messy `.env` files.

The configuration engine merges values in the following priority order (from lowest to highest):

1. **Framework Defaults (`//go:embed`)**: Tako's internal `config/*.yaml` files. These ensure the framework always works out-of-the-box even if you haven't created a single config
   file.
2. **App Defaults (`[AppDir]/config`)**: The configuration files checked into your application's repository. This is where you define your app's base settings.
3. **Local Dev Override (`.tako/config`)**: When running via `go run` (development mode), Tako reads from a local `.tako/config` folder. You can `.gitignore` this folder to safely
   store local database passwords or personal API keys.
4. **Production Override (`~/.my-app/config`)**: When your app is compiled and running as a binary on an end-user's machine, Tako reads from the user's home directory. This allows
   users to customize their local experience.

::note
When Tako merges configurations, it performs a **deep merge**. You only need to define the exact keys you want to override in the higher layers. For example, your
`.tako/config/database.yaml` only needs to contain `password: "secret"`, while inheriting the `dsn` and `pool_size` from `config/database.yaml`.
::

## Accessing Configuration Values

```go [providers/api/provider.go]
func (p *APIProvider) Boot(app *foundation.Application) error {
    // Three typed accessors — each accepts an optional default value
    baseURL    := app.Config().String("app.api.base_url", "http://localhost:8080")
    timeout    := app.Config().Int("app.api.timeout", 10)
    debug      := app.Config().Bool("app.debug", false)
    retryCount := app.Config().Int("app.api.retry_count", 1)

    app.Logger().Info("API provider initializing",
        "base_url", baseURL,
        "timeout", timeout,
        "debug", debug,
    )

    p.client = &APIClient{BaseURL: baseURL, Timeout: time.Duration(timeout) * time.Second}
    return nil
}
```

If a key doesn't exist and no default is provided, the zero value is returned (`""` for strings, `0` for integers, `false` for booleans). Always provide sensible defaults — it
makes the behavior explicit and prevents silent failures.

## Default Values

```go [provider.go]
// Without default — returns "" if missing (might cause empty API calls)
endpoint := app.Config().String("app.api.base_url")

// With default — safe fallback for local development
endpoint := app.Config().String("app.api.base_url", "http://localhost:8080")
```

Rule of thumb: if your code would behave incorrectly with the zero value, provide an explicit default.

## Environment Variable Overrides

Every configuration key can be overridden by an environment variable. Tako converts dot-notation keys to uppercase with underscores and a `TAKO_` prefix:

| Config Key         | Environment Variable    |
|--------------------|-------------------------|
| `app.name`         | `TAKO_APP_NAME`         |
| `app.api.base_url` | `TAKO_APP_API_BASE_URL` |
| `app.debug`        | `TAKO_APP_DEBUG`        |
| `database.dsn`     | `TAKO_DATABASE_DSN`     |

Environment variables always take precedence over file-based values:

```bash [terminal]
TAKO_APP_DEBUG=true TAKO_APP_API_BASE_URL=https://staging.api.com go run .
```

::warning
Environment variable values are always strings. When you call `Config().Int()` or `Config().Bool()`, Tako coerces via `strconv`. If coercion fails, the default is returned
silently. Use `"true"`/`"false"` for booleans, numeric strings for integers.
::

## Introspection

Dump the entire merged configuration from the CLI:

```bash [terminal]
go run . config:dump
```

Or programmatically:

```go [debug.go]
allConfig := app.Config().All()
for key, value := range allConfig {
    fmt.Printf("%s = %v\n", key, value)
}
```

## Custom Configuration Providers

For tests or alternative sources (remote key-value store, encrypted vault), bind your own `contracts.Config` before the bootstrap runs:

```go [main.go]
app := tako.NewApp()

// The LoadConfiguration bootstrapper checks for an existing binding.
// If one is found, it skips file loading entirely — your provider wins.
app.Container().Singleton(new(contracts.Config), &InMemoryConfig{
    "app.name":        "Test App",
    "app.api.base_url": "http://localhost:9999",
})

tako.Run(app)
```

## Thread Safety

The configuration system is read-only after boot and fully thread-safe. Reads from any goroutine — including concurrent provider `Boot` methods during bootstrap — are safe without
additional locking.

Now that you understand configuration, see [Directory Structure](/getting-started/directory-structure) to learn where config files live within the standard Tako project layout.

::tip
Split config files by domain, not by environment. Use `config/app.yaml` for application settings and `config/features.yaml` for feature flags. Override per-environment values with
environment variables in your deployment pipeline — no config file switching required.
::
