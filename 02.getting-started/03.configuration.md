Almost every application needs to be configured differently based on the environment it is running in. Whether it's the database path, logger settings, or API keys, Tako provides a
highly flexible configuration system to manage these values.

## The Config Directory

By default, Tako looks for a `config/` directory in the root of your project when it boots up. It automatically reads any `.yml` or `.yaml` files inside this directory and loads
them into memory.

You can organize your configurations into separate files based on their purpose:

```text
my-tako-app/
└── config/
    ├── app.yml
    ├── database.yml
    └── logging.yml
```

### Namespacing

When Tako loads a configuration file, it automatically uses the filename (without the `.yml` extension) as the "namespace" for the values inside it.

For example, if you create `config/app.yml` with the following content:

```yaml [config/app.yml]
name: "My Awesome App"
env: "development"
debug: true
```

You can access these values in your code using dot-notation, starting with the filename:

```go
name := app.Config().GetString("app.name") // Returns "My Awesome App"
debug := app.Config().GetBool("app.debug") // Returns true
```

## Retrieving Configuration Values

You can retrieve configuration values anywhere you have access to the `contracts.Application` instance (like inside a Service Provider or a Command Handle method) by calling
`app.Config()`.

The configuration repository provides several helpful methods with optional fallback values:

```go
// Get a string, defaulting to "local" if not found
env := app.Config().GetString("app.env", "local")

// Get a boolean, defaulting to false
debug := app.Config().GetBool("app.debug", false)

// Get an integer, defaulting to 8080
port := app.Config().GetInt("server.port", 8080)

// Get raw untyped data (returns `any`)
raw := app.Config().Get("database.connections")
```

## Environment Variables

Tako supports seamless integration with Environment Variables. Instead of hardcoding sensitive credentials or environment-specific paths in your `.yml` files, you can use the
special `{env:VAR_NAME}` syntax.

During the boot phase, Tako will automatically interpolate these values by reading them from your system's environment variables.

```yaml [config/database.yml]
connections:
  sqlite:
    driver: sqlite3
    # This will read the DB_PATH environment variable!
    database: "{env:DB_PATH}"
    timeout: 5000
```

If `DB_PATH` is set to `/var/data/my-app.db`, Tako will inject it directly into the configuration. If the environment variable does not exist, it will be replaced with an empty
string.

::tip
You do not need to install external libraries like `godotenv` unless you want to load a `.env` file into the OS environment before Tako starts. Tako relies purely on the OS
environment variables (`os.LookupEnv`).
::
