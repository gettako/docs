Hardcoding API URLs or toggling debug modes manually before compiling can lead to deployment issues. Tako addresses this by providing a `Config` manager that merges YAML files, environment variables, and defaults into a unified, typed interface.

## Configuration Hierarchy

Tako merges your configurations in the following priority order (highest to lowest):
1. **Dynamic Storage (`.tako/config/` or `~/.app-name/config/`)**: User-level overrides on the host machine.
2. **Project Level (`<project-root>/config/`)**: Developer-defined default configurations shipped with the application.
3. **Framework Default**: Internal fallback values provided by Tako.

## Creating Configuration Files

Let's set up the configuration for our **Server Dash**. Create a `config/` directory in your project root and add an `app.yml` file:

```yaml [config/app.yml]
name: ${APP_NAME:-"Server Dash"}
version: "1.0.0"
debug: ${APP_DEBUG:-true}

metrics:
  refresh_interval: 5s
  api_endpoint: ${API_ENDPOINT:-"https://api.example.com/v1/metrics"}
```

## Accessing Configuration

You can access the configuration anywhere in your code using the Context API or the `Config` manager. Tako automatically converts values into `cast.Value` wrappers, which reduces the need for manual type assertions.

Here is how you might read the configuration inside a Service Provider or your `main.go`:

```go
// Retrieve the Config service
cfg := app.Config()

// Read values with fallbacks and type casting
appName := cfg.Get("app.name", "Default App").String()
debugMode := cfg.Get("app.debug", false).Bool()
endpoint := cfg.Get("app.metrics.api_endpoint", "http://localhost").String()

app.Logger().Info("Configuration Loaded", 
    "name", appName, 
    "debug", debugMode,
    "endpoint", endpoint,
)

// You can also set or override configurations at runtime:
cfg.Set("app.debug", true).SetMany(map[string]any{
	"app.name": "Temporary Name",
})
```

::note
Notice the dot-notation (`app.metrics.api_endpoint`). Tako automatically namespaces YAML files based on their filename. Therefore, the `config/app.yml` file maps to the `app.*` configuration space.
::

## Environment Variables (.env & Interpolation)

Tako supports `.env` files natively. If you place a `.env` file in your project root, Tako will load it automatically. For production environments, Tako will also look for a `.env` file inside your dynamic storage path (e.g., `~/.app-name/.env`) as an override.

```env [.env]
APP_DEBUG=false
API_ENDPOINT="https://production-api.example.com/v1"
```

Tako supports **YAML Interpolation** similar to Docker Compose. Notice how we used `${APP_DEBUG:-true}` in our `app.yml`? Tako intercepts the YAML parsing and injects the value from the `.env` file or OS environment variables, falling back to the default value if it is missing.
