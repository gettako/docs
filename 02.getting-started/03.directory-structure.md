## The Standard Layout

```
myapp/
├── cmd/
│   └── main.go              # Application entry point
├── config/                  # (Optional) Core app settings and feature flags
├── lang/                    # (Optional) Translation dictionaries
├── providers/
│   ├── orders/
│   │   ├── provider.go      # ServiceProvider implementation
│   │   └── manifest.go      # Manifest constants
│   └── notifications/
│       └── provider.go
├── components/
│   ├── order_table.go       # Self-contained UI component
│   └── notification_panel.go
├── layouts/
│   └── base.go              # Root Layout implementing bubbletea.Layout
├── commands/
│   └── sync.go              # Custom CLI commands
├── services/
│   ├── api_client.go        # External API integration
│   └── cache.go
├── go.mod
├── go.sum
└── .gitignore               # Must include: .tako/
```

## Entry Point (`cmd/`)

```go [cmd/main.go]
package main

import (
	"log"

	"myapp/layouts"
	"myapp/providers"

	"gettako.dev/tako"
	"gettako.dev/tako/pkg/adapter/ui/bubbletea"
)

func main() {
	app := tako.NewApp()
	adapter := bubbletea.NewAdapter(app.Context(), &layouts.Base{})
	app.Mount(adapter)

	if err := tako.Run(app); err != nil {
		log.Fatal(err)
	}
}
```

All providers are registered explicitly via `app.RegisterProviders(...)`. No `init()` implicit behavior, no blank imports — what you see in `main.go` is what runs.

::tip
Some projects put `main.go` at the project root instead of `cmd/`. Both work. Use `cmd/` when you have multiple binaries (e.g., `cmd/myapp/main.go` and `cmd/migrate/main.go`).
::

## Configuration (`config/`)

```yaml [config/app.yaml]
name: "Inventory Manager"
version: "1.0.0"

api:
  endpoint: "https://api.warehouse.io"
  timeout: 15
```

Accessible as `app.name`, `app.version`, `app.api.endpoint`, and `app.api.timeout` via `ctx.Config()`. See the [Configuration](/getting-started/configuration) page for full
details.

::note
The `config/` and `lang/` directories are completely **optional**. You do not need to create them if your application does not require external configuration or translations. Tako
does not auto-create them.
::

## Providers (`providers/`)

Each provider gets its own subdirectory with a ServiceProvider implementation:

```go [providers/orders/provider.go]
package orders

import (
    "gettako.dev/tako/contracts"
    "gettako.dev/tako/pkg/foundation"
)

type OrderProvider struct{}

func (p *OrderProvider) Register(app *foundation.Application) error {
    return nil
}

func (p *OrderProvider) Boot(app *foundation.Application) error {
    app.Events().Subscribe(app.Context(), "order:created", func(e contracts.Event) {
        // handle order
    })
    return nil
}
```

Keeping each provider isolated in its own package enforces clear boundaries. One provider's internals never bleed into another's.

## Components (`components/`)

Components are self-contained UI widgets that bundle rendering, keybindings, and mouse handling behind the `contracts.Component` interface:

```go [components/order_table.go]
package components

import "gettako.dev/tako/contracts"

type OrderTable struct {
    orders   []*Order
    selected int
}

func (t *OrderTable) ID() string  { return "order-table" }
func (t *OrderTable) Render() any { return t.renderRows() }
func (t *OrderTable) RegisterKeys(keys contracts.KeyManager) {
    keys.Zone(t.ID()).Bind("j|down", func() { t.moveDown() })
    keys.Zone(t.ID()).Bind("k|up", func() { t.moveUp() })
    keys.Zone(t.ID()).Bind("enter", func() { t.openSelected() })
}
```

Components are displayed via `app.UI().MountOverlay(&OrderTable{})`. The framework automatically wires the render hook, pushes the stack layer, and registers the keybindings.

## Layouts (`layouts/`)

A layout is your application's root view structure. With the Bubble Tea adapter, implement the `bubbletea.Layout` interface with a single `View` method:

```go [layouts/base.go]
package layouts

import (
    tea "charm.land/bubbletea/v2"
    "gettako.dev/tako/internal/router"
    "gettako.dev/tako/internal/tako"
)

type Base struct{}

func (b *Base) View(ctx *tako.Context) tea.View {
    // Compose from hooks provided by providers
    toolbar := ctx.Hooks().Get("render:toolbar")
    sidebar := ctx.Hooks().All("app.sidebar")
    overlay := ctx.Hooks().Get("tako.overlay." + r.Stack().Top())

    // Build your terminal UI string here...
    output := renderAll(toolbar, sidebar, overlay)

    view := tea.NewView(output)
    view.AltScreen = true
    return view
}
```

## Commands (`commands/`)

Custom CLI commands implement the `cli.Command` interface:

```go [commands/sync.go]
package commands

import "gettako.dev/tako/internal/console/cli"

type SyncCommand struct{}

func (c *SyncCommand) Name() string        { return "sync" }
func (c *SyncCommand) Description() string { return "Sync local data with remote API" }
func (c *SyncCommand) Execute(ctx *cli.Context, args []string) error {
    ctx.Info("Syncing...")
    return performSync(ctx)
}
```

Register from a provider or from `main.go`:

```go
app.Commands(&commands.SyncCommand{})
```

## Services (`services/`)

Business logic not tied to the TUI or provider lifecycle lives here. Typically registered in the IoC container so providers resolve them without direct imports:

```go [services/api_client.go]
package services

type APIClient struct {
    BaseURL string
    Timeout time.Duration
}

func NewAPIClient(baseURL string, timeout time.Duration) *APIClient {
    return &APIClient{BaseURL: baseURL, Timeout: timeout}
}
```

```go [registration.go]
app.Container().Singleton(new(*services.APIClient), services.NewAPIClient(
    app.Config().String("app.api.endpoint"),
    time.Duration(app.Config().Int("app.api.timeout", 10))*time.Second,
))
```

## Runtime Directory (`.tako/`)

Tako creates a `.tako/` directory in your project root for runtime data. **Add it to `.gitignore` from day one.**

Beyond storing temporary files, this directory acts as a **simulation of the user's home directory** during development (`go run .`). This allows you to test production-like
overrides (like `~/.my-app/config/` or `~/.my-app/lang/`) locally without cluttering your actual home directory or committing secrets to version control.

| Path                   | Contents                                           |
|------------------------|----------------------------------------------------|
| `.tako/logs/tako.log`  | Structured file logger output                      |
| `.tako/data/kv.db`     | Persistent key-value store                         |
| `.tako/run/*.json`     | DevTools PID file (dev mode)                       |
| `.tako/traces/*.jsonl` | Event recorder trace files (`TAKO_RECORD_TRACE=1`) |
| `.tako/config/`        | Local configuration overrides (dev mode)           |
| `.tako/lang/`          | Local language dictionary overrides (dev mode)     |

::caution
Never commit `.tako/` to version control. It contains runtime state, potentially sensitive auth tokens, local overrides, and machine-specific paths.
::

## Starting Simple

You don't need all of this on day one. A valid minimal starting point is:

```
myapp/
├── main.go
├── layout.go
├── go.mod
└── go.sum
```

Add directories as complexity arrives — not to anticipate it. The conventions exist to guide you when you feel the friction, not to impose ceremony on a prototype.

Now that you know where things live, [Application Lifecycle](/architecture/application-lifecycle) shows exactly what happens when Tako boots — from the first `NewApp()` call
through the bootstrap sequence to the running event loop.

::tip
Keep `providers/` as your primary boundary. One provider per business domain (`orders`, `inventory`, `notifications`, `auth`). A provider that needs to import another provider's
package is a design smell — refactor the shared concern into state, an event, or an RPC route instead.
::
