## Requirements

- **Go 1.23** or later (`go version` to check)
- A module-aware project (`go.mod`)
- A terminal emulator with ANSI support — virtually all modern terminals qualify

::note
Tako has no CGO dependencies and no code generation steps. It runs anywhere Go compiles — including CI environments, Docker containers, and remote SSH sessions.
::

## Installing the Framework

```bash [terminal]
mkdir myapp && cd myapp
go mod init myapp
go get gettako.dev/tako
```

This gives you the framework's full core: service container, event bus, provider manager, routing engine, state management, CLI system, and all public contracts (interfaces).

## Installing a UI Adapter

Tako is UI-agnostic. The framework handles structure and logic; a separate adapter handles terminal rendering. The official adapter
uses [Bubble Tea](https://github.com/charmbracelet/bubbletea):

```bash [terminal]
go get gettako.dev/tako/pkg/adapter/ui/bubbletea
```

If you prefer tcell, termbox, or something entirely custom — skip this step and implement `contracts.UIRenderer` yourself. See [Custom Adapters](/extending/custom-adapters).

::tip
The Bubble Tea adapter handles the terminal event loop, alt-screen management, mouse event translation, and bus event forwarding. Tako handles the view composition under the hood.
::

## Your First Application

```go [main.go]
package main

import (
    "log"

    "gettako.dev/tako"
    "gettako.dev/tako/pkg/adapter/ui/bubbletea"
)

func main() {
    app := tako.NewApp()

    // Mount the layout component
    app.UI().Layout(&DashboardLayout{})

    // Mount the terminal adapter
    app.Mount(bubbletea.NewAdapter(app.Context(), nil))

    if err := tako.Run(app); err != nil {
        log.Fatal(err)
    }
}
```

```go [layout.go]
package main

import (
    "gettako.dev/tako/contracts"
)

type DashboardLayout struct{}

func (d *DashboardLayout) ID() string {
    return "dashboard"
}

func (d *DashboardLayout) Render() any {
    return "Dashboard ready. Press ctrl+c to exit.\n"
}

func (d *DashboardLayout) RegisterKeys(keys contracts.KeyManager) {}
```

```bash [terminal]
go run -race .
```

You'll see your message in alt-screen mode. Press `ctrl+c` to exit — Tako's default smart-quit handler closes overlays first, then shuts down the app (this can be disabled using
`tako.NewApp().WithoutDefaultQuit()`).

::tip
**Always use `-race` during development!** Tako is highly concurrent, with events, components, and async operations running in multiple goroutines. The Go race detector (`-race`)
will instantly flag any unsafe state mutations before they become hard-to-debug crashes in production.
::

## What Happened Under the Hood

When `tako.Run(app)` was called, the framework:

1. **Constructed the application** — Created an IoC container, registered core services (EventBus, StateManager, ThemeManager, Router, UIManager, Scheduler), and bound the default
   `ctrl+c` smart-quit handler.
2. **Registered your adapter** — Stored the Bubble Tea adapter as the `contracts.UIRenderer` binding.
3. **Ran the bootstrap sequence** — Created data directories, initialized the file logger, opened the KV store, loaded config files from `config/`, registered built-in CLI
   commands, booted registered providers.
4. **Selected the TUI kernel** — No CLI arguments detected, so Tako resolved the `UIRenderer` and entered the Bubble Tea event loop.
5. **Started the event loop** — The adapter owns the terminal, routing key presses through the router, flushing events each tick, calling your layout's `View` method for each
   frame.

All of this is configurable, extensible, and replaceable — but none of it requires upfront configuration.

## Running as a CLI Tool

Every Tako application doubles as a CLI tool. Pass any argument and Tako routes to the CLI kernel instead of the TUI:

```bash [terminal]
go run . help
go run . plugin:list
go run . version
go run . status
```

You get a suite of built-in commands for free. The [CLI Commands](/cli/commands) section covers this in full.

Now that your application boots, head to [Configuration](/getting-started/configuration) to learn how Tako loads YAML and JSON config files, or jump
to [Directory Structure](/getting-started/directory-structure) to see how a well-organized Tako project is laid out.

::tip
**Pro-Tip:** During early development, run your app with `TAKO_DEBUG=1 go run -race .` to enable verbose event logging. You'll see every event flowing through the bus printed to
stderr — invaluable for understanding initialization order and debugging provider wiring before you've built a UI.
::
