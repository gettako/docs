## General

### Can I use Tako without providers?

Yes. Providers provide organizational structure, but you can register keys, hooks, and events directly in `main.go`. However, as your application grows, using providers keeps the
codebase maintainable.

### Can I use Tako without Bubble Tea?

Yes. Tako is UI-agnostic. Implement `contracts.UIRenderer` with any rendering library (tcell, termbox, etc.).

### Is Tako thread-safe?

Yes. Core services (Container, EventBus, StateManager, Router, Hooks, Scheduler) are thread-safe and can be called concurrently from background goroutines without locking.

### Does Tako support Windows?

Yes. Tako relies on `golang.org/x/term` and Bubble Tea, both of which have excellent cross-platform support including Windows Command Prompt, PowerShell, and Windows Terminal.

## Architecture & Design

### Why does the Cron scheduler have zero dependencies?

To keep the binary size small and eliminate supply-chain risks for critical components. Tako's built-in cron parser handles standard 5-field expressions (including ranges, lists,
and steps) natively, covering 95% of TUI daemon use cases without bloating `go.mod`.

### Why does Tako use a Service Container?

In a complex TUI, different components (UI, background pollers, API clients, local storage) need to interact. A Service Container (IoC) prevents "spaghetti dependency passing"
where you have to pass 10 arguments through multiple layers of constructors just to get a logger down to a deeply nested component.

### How do I persist data between sessions?

Use the built-in [KV Storage](/state-management/kv-storage). It's a thread-safe, local JSON-based storage engine that automatically handles reading and writing to
`.tako/data/kv.db`.

## Development & Debugging

### How do I debug what's happening?

- **Live**: `go run . inspect` (DevTools)
- **Post-mortem**: `TAKO_RECORD_TRACE=1 go run .` followed by `go run . replay` (Time Travel)
- **Logs**: Read `.tako/logs/tako.log`

### Can I run tests without a terminal attached?

Yes! Since Tako decouples application logic from presentation via the Service Container and Hooks, you can mock `contracts.UIRenderer` and test your business logic purely via Go
tests. See [Testing](/testing) for details.
