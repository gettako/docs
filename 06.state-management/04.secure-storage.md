Tako's default `KVStore` stores data as plain JSON in the `.tako/data/kv.db` file. This is perfect for themes, preferences, and focus state, but **unsafe** for passwords or API
tokens.

To store sensitive data securely (*Encryption at Rest*), Tako provides a separate `secure` adapter that delegates to the OS-native credential manager (macOS Keychain, Linux Secret
Service, Windows Credential Manager).

## Why a Separate Module?

OS Keychain access (`go-keyring`) involves complex OS-level dependencies (like requiring CGO on Linux for D-Bus). If Tako included this library in its core package, it would bloat
the framework and break cross-compilation for all applications, even those that don't need secure storage.

By extracting it into a separate nested module, Tako's core remains 100% zero-dependency and lightweight. You only pay for what you use.

## How to Use Secure Store

### 1. Installation

Download the `secure` module to your project:

```bash
go get gettako.dev/tako/pkg/adapter/storage/secure
```

### 2. Registration

Since secure storage is an optional module, you activate it by registering its `ServiceProvider`. This provider will automatically wrap Tako's default storage during the
application boot process.

```go [main.go]
package main

import (
    "gettako.dev/tako"
    "gettako.dev/tako/pkg/adapter/storage/secure"
)

func main() {
    app := tako.NewApp()

    // Register the secure storage provider
    app.RegisterProviders(
        new(secure.Provider),
    )

    // Continue to mount UI and run the app...
}
```

### 3. Dynamic Configuration

Registering the provider opts you in to using secure storage (and downloads the necessary OS dependencies). However, you can dynamically disable it without changing your code by
editing `config/storage.yaml` or setting an environment variable (`TAKO_STORAGE_SECURE=false`).

```yaml [config/storage.yaml]
# Whether to enable the OS-level secure storage (Keychain/Credential Manager).
# This only takes effect if the secure.Provider is registered in main.go.
secure: false
```

If `secure` is set to `false`, the provider gracefully steps aside and all secrets will fall back to being stored in the standard unencrypted JSON file.

### 4. Reading & Writing Secrets

Once the adapter is mounted, use the `SetSecret` and `GetSecret` methods available on the `KVStore` interface.

```go [provider.go]
func (p *AuthProvider) Boot(app *foundation.Application) error {
    store := app.Context().Storage()

    type Credentials struct {
        Token     string `json:"token"`
        ExpiredAt string `json:"expired_at"`
    }

    // Write Normal Data (Stored in plain JSON file)
    store.Set("user:email", "admin@tako.dev")

    // Write Secret Data (Stored in OS Keychain)
    creds := Credentials{Token: "eyJhbG..."}
    if err := store.SetSecret("auth:creds", creds); err != nil {
        return err
    }

    // Read Secret Data
    var loaded Credentials
    if err := store.GetSecret("auth:creds", &loaded); err != nil {
        app.Context().Logger().Warn("token not found", "err", err)
    }

    return nil
}
```

## How It Works

The `secure` adapter acts as a proxy (wrapper).

- If you call `Set`, `Get`, `Has`, or `Delete`, it forwards the command to the base storage (`FileKVStore`), so the data goes into the plain JSON file.
- If you call `SetSecret` or `GetSecret`, the adapter converts your value into a JSON string and sends it to the **OS Keychain** using the namespace automatically resolved from
  your app's binary name (or the custom name if you used `secure.NewWithService()`).

## Deleting Secrets

The `Delete(key string)` method is designed to attempt deleting the key from both the Keychain and the base storage simultaneously. This allows you to safely use `Delete` without
needing to remember where the data was stored.

```go
// Deletes data from the OS keychain permanently
store.Delete("auth:creds")
```
