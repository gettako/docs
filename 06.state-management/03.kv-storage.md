KV Storage persists data to disk using JSON serialization. Unlike the state manager (which lives only for the session), KV values survive restarts. Use it for user preferences,
session tokens, focus stack state, and any application data that should outlast the current process.

## Basic Operations

```go [providers/preferences/provider.go]
func (p *PreferencesProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    store := ctx.Storage()

    // Set — serializes to JSON and writes to disk
    prefs := &UserPreferences{
        Theme:      "dracula",
        FontSize:   14,
        TabWidth:   4,
        AutoSave:   true,
    }
    if err := store.Set("user:preferences", prefs); err != nil {
        ctx.Logger().Error("failed to persist preferences", "err", err)
    }

    // Has — check existence before Get to avoid nil assertions
    if !store.Has("user:preferences") {
        store.Set("user:preferences", defaultPreferences())
    }

    // Get — deserializes JSON into the provided pointer
    var loaded UserPreferences
    if err := store.Get("user:preferences", &loaded); err != nil {
        ctx.Logger().Warn("preferences corrupted, using defaults", "err", err)
        loaded = *defaultPreferences()
    }

    // Delete — removes the key permanently
    store.Delete("user:onboarding_dismissed")

    // Secrets — use SetSecret/GetSecret for sensitive data
    // Note: By default, this is still plain text! See "Secrets & Encryption" below.
    store.SetSecret("auth:token", "eyJhbG...")
    return nil
}
```

`Get` requires a pointer. If the stored JSON doesn't match the target type, you get a descriptive error — handle it by falling back to defaults. Never crash on a corrupted
preferences file.

## JSON Serialization

KV uses `encoding/json`. Any struct with `json` tags works:

```go [types.go]
type UserPreferences struct {
    Theme      string            `json:"theme"`
    FontSize   int               `json:"font_size"`
    RecentDirs []string          `json:"recent_dirs"`
    Shortcuts  map[string]string `json:"shortcuts"`
    AutoSave   bool              `json:"auto_save"`
}
```

The storage file at `.tako/data/kv.db` is plain readable JSON:

```json [.tako/data/kv.db]
{
    "user:preferences": {
        "theme": "dracula",
        "font_size": 14,
        "auto_save": true,
        "recent_dirs": ["/home/user/projects", "/tmp/scratch"]
    },
    "auth:last_session": {
        "user_id": "usr_12345",
        "expires_at": "2025-03-15T10:30:00Z"
    },
    "router.stack": ["base"]
}
```

::caution
**Never store secrets in plain KV.** API keys, passwords, and auth tokens are readable by any process with filesystem access if using the default `FileKVStore`.
::

## Secrets & Encryption

Tako's `contracts.KVStore` provides two special methods for sensitive data:

- `SetSecret(key string, val any) error`
- `GetSecret(key string, ptr any) error`

**Important:** The default `FileKVStore` implements these by simply passing them through to standard `Set` and `Get` (plain text JSON). This keeps Tako zero-dependency out of the
box.

To enable Encryption at Rest (e.g. using the OS Keychain), you must bind a `securestore` adapter to the container, which implements `GetSecret` and `SetSecret` with real encryption
while continuing to use standard storage for non-sensitive data.

```go
// Example: Binding a custom secure storage adapter
app.WithStorage(mySecureStoreAdapter)
```

## Access via Context

KV is registered during bootstrap and available through `ctx.Storage()`:

```go [providers/theme/provider.go]
func (p *ThemeProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    store := ctx.Storage()

    // Load active theme — fall back to default if never set
    var theme ThemeConfig
    if store.Has("theme:active") {
        if err := store.Get("theme:active", &theme); err != nil {
            theme = DefaultTheme()
        }
    } else {
        theme = DefaultTheme()
    }

    // Load into state so all providers can observe it reactively
    ctx.State().Produce().
        Mutate("theme:active").
        Value(theme).
        Pin(). // Don't LRU-evict this
        Broadcast().
        Set()

    // Persist when theme changes
    ctx.State().Watch("theme:active").
        Debounce(500 * time.Millisecond).
        OnUpdate(func(_, new any) {
            store.Set("theme:active", new.(ThemeConfig))
        }).
        Subscribe(ctx.Context)
    return nil
}
```

## The Standard Pattern: KV ↔ State Bridge

Load from KV into state at init, auto-persist on state change:

```go [providers/preferences/provider.go]
func (p *PreferencesProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    p.app = app // save app instance for Shutdown

    // 1. Load from disk (or use defaults on first run)
    prefs := defaultPreferences()
    if ctx.Storage().Has("user:prefs") {
        ctx.Storage().Get("user:prefs", prefs)
    }

    // 2. Make reactive via state manager
    ctx.State().Produce().
        Mutate("user:prefs").
        Value(prefs).
        Pin().
        Broadcast().
        Set()

    // 3. Auto-persist on change
    ctx.State().Watch("user:prefs").
        Debounce(1 * time.Second). // Batch rapid changes
        OnUpdate(func(_, new any) {
            ctx.Storage().Set("user:prefs", new.(*UserPreferences))
        }).
        Subscribe(ctx.Context)
    return nil
}

func (p *PreferencesProvider) Shutdown() error {
    // Final sync — the observer may not have fired for the last change
    ctx := p.app.Context()
    if v := ctx.State().Get("user:prefs"); v != nil {
        ctx.Storage().Set("user:prefs", v.(*UserPreferences))
    }
    return nil
}
```

This pattern gives you:

- **Reactivity during the session** — state manager observers work normally
- **Durability across sessions** — changes auto-persist to KV
- **Resilience** — if the app crashes, the last debounce-flushed value is preserved

::tip
Keep KV keys in a centralized constants file — one per provider, or one shared `storage/keys.go`. String constants prevent typos that silently fail, and a single file gives new
developers a complete map of what each provider stores. Name your keys `"providername:data_name"` to make the storage file human-readable when inspected.
::
