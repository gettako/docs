Observers are focused watchers for individual state keys. You subscribe to `"state:changed"` and manually filter by key — or you use an observer and write a handler that fires only
for the key you care about, with debouncing built-in and lifecycle management automatic.

## The Fluent Observer API

```go [providers/cart/provider.go]
func (p *CartProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    // Fires when "cart:items" changes, coalesced to 100ms bursts
    itemsWatcher := ctx.State().Watch("cart:items")
    itemsWatcher.Debounce(100 * time.Millisecond)
    itemsWatcher.OnUpdate(func(old, new any) {
        items := new.([]*CartItem)
        var total float64
        for _, item := range items {
            total += item.Price * float64(item.Quantity)
        }
        // Write derived state — triggers its own observers
        ctx.State().Set("cart:total", total)
    })
    itemsWatcher.Subscribe(ctx.Context()) // Binds lifetime to provider context — auto-cleaned up

    // Watch "cart:total" separately for UI refresh
    totalWatcher := ctx.State().Watch("cart:total")
    totalWatcher.Debounce(50 * time.Millisecond)
    totalWatcher.OnUpdate(func(old, new any) {
        ctx.State().Set("cart:display_total", fmt.Sprintf("$%.2f", new.(float64)))
    })
    totalWatcher.Subscribe(ctx.Context())
    return nil
}
```

`Subscribe(ctx.Context)` is the terminal call. The observer fires until the context is cancelled — no manual unsubscription needed.

## Debouncing

Debouncing is essential for keys that change at high frequency (typed search queries, resize events, batch imports). Without it, every intermediate value triggers your handler:

```go [providers/search/provider.go]
func (p *SearchProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    // Without debounce: handler fires 12 times as user types "hello world"
    // With debounce(250ms): handler fires once, 250ms after they stop typing
    watcher := ctx.State().Watch("search:query")
    watcher.Debounce(250 * time.Millisecond)
    watcher.OnUpdate(func(old, new any) {
        query := new.(string)
        if len(query) < 2 {
            ctx.State().Set("search:results", []Result{})
            return
        }
        results := p.executeSearch(query)
        ctx.State().Set("search:results", results)
    })
    watcher.Subscribe(ctx.Context())
    return nil
}
```

::tip
A good default debounce is 100–250ms for UI triggers, and 500ms–1s for write operations (like persisting to KV storage).
::

## Filtering by Delta

The `OnUpdate` callback receives both old and new values. Use this to avoid unnecessary work when the computed output hasn't changed:

```go [providers/inventory/provider.go]
watcher := ctx.State().Watch("inventory:stock_levels")
watcher.Debounce(500 * time.Millisecond)
watcher.OnUpdate(func(old, new any) {
    oldLevels := old.(map[string]int)
    newLevels := new.(map[string]int)

    // Only emit alerts for items that newly went out of stock
    for sku, qty := range newLevels {
        if qty == 0 && oldLevels[sku] > 0 {
            ctx.Emit("inventory:stock_alert", StockAlert{
                SKU:     sku,
                Level:   qty,
                Message: fmt.Sprintf("%s is now out of stock", sku),
            })
        }
    }
})
watcher.Subscribe(ctx.Context())
```

## Multiple Observers for One Key

You can register multiple observers for the same key. Each is independent:

```go [providers/order_tracker/provider.go]
func (p *OrderProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    // Observer 1: update badge count
    badgeWatcher := ctx.State().Watch("orders:active")
    badgeWatcher.Debounce(100 * time.Millisecond)
    badgeWatcher.OnUpdate(func(_, new any) {
        ctx.Hooks().Set("render:order_badge", func() any {
            return fmt.Sprintf("Orders: %d", len(new.([]*Order)))
        })
    })
    badgeWatcher.Subscribe(ctx.Context())

    // Observer 2: log changes for audit
    auditWatcher := ctx.State().Watch("orders:active")
    auditWatcher.Debounce(1 * time.Second)
    auditWatcher.OnUpdate(func(old, new any) {
        ctx.Logger().Info("active orders changed",
            "from", len(old.([]*Order)),
            "to",   len(new.([]*Order)),
        )
    })
    auditWatcher.Subscribe(ctx.Context())
    return nil
}
```

Each observer has its own debounce timer — they don't share one.

## Derived State with Observer Chains

Observers compose naturally into reactive computation graphs:

```mermaid
flowchart LR
    S1[("State: cart:items")] -->|Watch (100ms)| O1(Observer 1)
    O1 -->|Compute & Set| S2[("State: cart:subtotal")]
    
    S2 -->|Watch (50ms)| O2(Observer 2)
    O2 -->|Apply Discount & Set| S3[("State: cart:total")]
    
    S3 -->|Watch (50ms)| O3(Observer 3)
    O3 -->|Format & Set| S4[("State: cart:display_total")]
    
    classDef state fill:#1e293b,stroke:#64748b,color:#fff,stroke-width:2px
    classDef obs fill:#0f172a,stroke:#38bdf8,stroke-dasharray: 5 5
    class S1,S2,S3,S4 state
    class O1,O2,O3 obs
```

```go [observers.go]
// Level 1: compute raw total from cart items
itemsWatcher := ctx.State().Watch("cart:items")
itemsWatcher.Debounce(100 * time.Millisecond)
itemsWatcher.OnUpdate(func(_, new any) {
    total := computeTotal(new.([]*CartItem))
    ctx.State().Set("cart:subtotal", total)
})
itemsWatcher.Subscribe(ctx.Context())

// Level 2: apply discount to arrive at final total
subtotalWatcher := ctx.State().Watch("cart:subtotal")
subtotalWatcher.Debounce(50 * time.Millisecond)
subtotalWatcher.OnUpdate(func(_, new any) {
    subtotal := new.(float64)
    discount := ctx.State().Get("cart:discount_rate").(float64)
    ctx.State().Set("cart:total", subtotal*(1-discount))
})
subtotalWatcher.Subscribe(ctx.Context())

// Level 3: format for display
totalWatcher := ctx.State().Watch("cart:total")
totalWatcher.Debounce(50 * time.Millisecond)
totalWatcher.OnUpdate(func(_, new any) {
    ctx.State().Set("cart:display_total", fmt.Sprintf("$%.2f", new.(float64)))
})
totalWatcher.Subscribe(ctx.Context())
```

Changes to `"cart:items"` cascade through the chain automatically, with each level debounced independently.

## Lifecycle Binding

`Subscribe(ctx.Context)` binds the observer to the provider context. When the provider is destroyed (or the context is cancelled), the observer is removed. No manual cleanup.

For observers that should live for the entire application lifetime, use `app.Events().Subscribe(context.Background(), "state:changed", ...)` instead — but this gives up the
key-filtering and debouncing benefits.

::tip
Don't chain too many observer levels without profiling. Each level adds a debounce delay. If you have a 5-level reactive chain with 100ms debounce at each level, a single change
takes up to 500ms to propagate end-to-end. For deeply nested derived state, consider computing all derived values in one observer and writing multiple state keys at once — fewer
levels, same result.
::
