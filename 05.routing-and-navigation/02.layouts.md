When building a Terminal User Interface, you rarely want the entire screen to completely clear and redraw from scratch every time you navigate to a new route. Typically, you have persistent elements—like a Top Bar, a Sidebar, or a Footer—that remain visible while only the main content area changes.

Tako solves this elegantly using **Layouts**.

## The Layout Contract

A Layout is a special type of View that implements the `contracts.Layout` interface. It is exactly like a normal View, but it requires an additional `SetContent(view View)` method.

```go
package components

import (
	"gettako.dev/tako/contracts"
)

type AppLayout struct {
	content contracts.View
}

// SetContent is called automatically by the Router when a child route is activated
func (l *AppLayout) SetContent(view contracts.View) {
	l.content = view
}

// Render draws the persistent frame around the child view
func (l *AppLayout) Render(ctx contracts.Context) string {
	header := "=== TAKO DASHBOARD ==="
	
	var mainArea string
	if l.content != nil {
		mainArea = l.content.Render(ctx)
	}

	footer := "Press 'Q' to quit"

	// You would typically use Lipgloss here to stitch these together beautifully
	return header + "\n\n" + mainArea + "\n\n" + footer
}
```

## Applying Layouts to Routes

To apply a layout, you use the `router.Root()` method. This method takes an instance of a layout and a closure containing all the routes that should be rendered *inside* that layout.

```go
func (p *AppProvider) Boot(app contracts.Application) {
	router := app.TUI().Router()
	
	// Create a single, persistent instance of the layout
	layout := &components.AppLayout{}

	// Any route defined inside this closure will be injected into 'layout'
	router.Root(layout, func() {
		router.Route("home", func() contracts.View { return &components.HomeView{} })
		router.Route("settings", func() contracts.View { return &components.SettingsView{} })
	})

	// Routes outside the closure will NOT use the layout (e.g. fullscreen login)
	router.Route("login", func() contracts.View { return &components.LoginView{} })
}
```

### How it Works

When you call `router.Navigate("settings")`:
1. The Router sees that `settings` is wrapped by `AppLayout`.
2. It instantiates `SettingsView`.
3. It calls `layout.SetContent(SettingsView)`.
4. It calls `layout.Render(ctx)`.

Because the layout instance is persistent, any internal state within the layout (like the currently highlighted sidebar menu item) is naturally preserved across navigations!
