If you have built a single-page web application (SPA) using React Router or Vue Router, Tako's routing system will feel familiar.

In traditional TUI development, managing which screen is currently active requires managing `switch` statements and state machines. Tako abstracts this by binding isolated components to routes, allowing navigation similar to web applications.

## The Router 

The Router (`contracts.Router`) is the core routing mechanism of your visual application. When you initialize your application with `tako.NewApp()`, the Router is automatically configured, bound to the container, and ready to use.

## Defining Routes

You define routes by calling the `Route()` method. A route requires a URL-like path (e.g., `/dashboard`) and a Component that implements `contracts.Component`.

Let's register some basic routes for our Server Dash. Usually, this is done before you call `tako.Run(app)`:

```go
func main() {
	app := tako.NewApp()

	// Map the root path to a Home component
	app.Router().Route("/", components.NewHome()).Name("home")

	// Map to a Dashboard component
	app.Router().Route("/dashboard", components.NewDashboard()).Name("dashboard")

	// Set the default starting screen
	app.Router().GoTo("home")

	tako.Run(app)
}
```

::note
We recommend attaching a `.Name()` to your routes. Navigating by names is safer, reduces path typos, and makes refactoring easier.
::

## Dynamic Parameters

Tako supports URL-like dynamic parameters in your paths. If you want to view the details of a specific server, you can use the `:param` syntax as you would in a web framework.

```go
app.Router().Route("/servers/:id", components.NewServerDetail()).Name("servers.show")
```

To extract that `:id` parameter when the user visits the route, your component implements the `contracts.RouteAware` interface. This provides an `OnRouteUpdate` hook that fires whenever the component is navigated to.

```go
type ServerDetail struct {
	serverID string
}

// OnRouteUpdate implements contracts.RouteAware
func (c *ServerDetail) OnRouteUpdate(ctx contracts.Context, params map[string]string) {
	// Extract the dynamic parameter
	if id, exists := params["id"]; exists {
		c.serverID = id
	}
}

func (c *ServerDetail) Render() string {
	return fmt.Sprintf("Viewing details for Server: %s", c.serverID)
}
```

## Navigating Between Routes

To switch the active screen from anywhere in your app, you trigger a navigation event via the Context or Router instance.

### 1. `GoTo` (Navigate by Name)
This is the recommended way to navigate. It pushes the new route onto the history stack.

```go
// Simple navigation
ctx.Router().GoTo("dashboard")

// Navigation with dynamic parameters
ctx.Router().GoTo("servers.show", contracts.Params{"id": "ubuntu-db-1"})
```

### 2. `GoToPath` (Navigate by Path)
If you need to navigate based on a raw string path (for example, if a user typed a command in a search bar), you can use `GoToPath`.

```go
ctx.Router().GoToPath("/servers/ubuntu-db-1")
```

### 3. `Replace`
If you want to navigate but **do not** want to leave a trace in the back-history (for example, redirecting from a Login screen to the Dashboard), use `Replace`. This prevents the user from accidentally navigating "back" into a logged-out screen.

```go
ctx.Router().Replace("dashboard")
```

### 4. `Back`
To return to the previous screen in the history stack, simply call:

```go
ctx.Router().Back()
```

## Layouts

Many web applications share a common shell—like a navigation bar or a sidebar—across multiple pages. Tako supports this via the `Root()` method.

```go
// All routes inside this closure will be rendered INSIDE the MainLayout component!
app.Router().Root(components.NewMainLayout(), func(r contracts.Router) {
	r.Route("/dashboard", components.NewDashboard()).Name("dashboard")
	r.Route("/settings", components.NewSettings()).Name("settings")
})
```

The `MainLayout` component acts as the parent and receives the currently active sub-route's rendered string, allowing it to frame the content within a consistent UI shell.

## Checking Route Existence

To check if a named route is registered without triggering any middleware or navigation, use `HasRoute()`. This is useful for dynamically showing or hiding navigation elements based on what routes are available:

```go
if ctx.Router().HasRoute("admin.panel") {
    // Render the Admin link in the sidebar
}
```

## Route Metadata

You can attach arbitrary metadata to any route using the `.Meta()` method. This metadata is available in `RouteInfo.Meta` during navigation and in middleware, enabling declarative route guard patterns:

```go
app.Router().Route("/admin", components.NewAdmin()).
    Name("admin").
    Meta(map[string]any{
        "auth": true,
        "role": "admin",
    })
```

The metadata is readable in any middleware:
```go
app.Router().Use(func(ctx contracts.Context, to contracts.RouteInfo) bool {
    if to.Meta["auth"] == true {
        return ctx.Auth().IsLoggedIn()
    }
    return true
})
```

It is also available on the current active route:
```go
meta := ctx.Router().Current().Meta
if meta["role"] == "admin" {
    // Show admin controls
}
```
