While you can build a Tako application with a single [View](/the-basics/views), most applications need multiple screens (for example, navigating from a Main Menu to a Settings page).

Tako provides a built-in stack-based Router that handles navigating between screens, maintaining a history stack (so you can go "back"), and applying persistent layouts.

## Basic Routing

To use the router, you retrieve it from the TUI Kernel and register your views. Every route requires a path, a factory function that returns your view, and a unique name.

```go
func main() {
	app := tako.NewApp()
	router := app.TUI().Router()

	// Register the home screen
	router.Route("/", func() contracts.View {
		return &components.HomeScreen{}
	}).Name("home")

	// Register a settings screen
	router.Route("/settings", func() contracts.View {
		return &components.SettingsScreen{}
	}).Name("settings")

	// Navigate to the initial route
	router.Navigate("home")

	tako.Run(app)
}
```

::note
Notice that we pass a **factory function** (`func() contracts.View`) instead of passing the struct directly. This is extremely important! It ensures that a completely fresh instance of your View is created every time the user navigates to it, preventing stale state from leaking across visits.
::

## Navigation

Once your routes are registered, navigating between them is simple. You navigate using the **Name** of the route, not the path.

### Using the Router from the Context

Inside your View's Action handlers or Keybinds, you can retrieve the Router from the context:

```go
func (s *HomeScreen) Keys(km contracts.InputManager) {
	km.Bind("s", func(ctx contracts.InputContext) {
		// Navigate forward
		ctx.Router().Navigate("settings")
	})
}
```

### Going Back

Because Tako maintains a navigation history stack, you can easily pop the current screen off the stack and return to the previous one without needing to know what the previous one was!

```go
func (s *SettingsScreen) Keys(km contracts.InputManager) {
	km.Bind("esc", func(ctx contracts.InputContext) {
		// Navigate backward
		ctx.Router().Back()
	})
}
```

## Persistent Layouts

In many applications, you want a persistent UI element (like a header, sidebar, or footer) to remain on the screen while the central content changes. Tako solves this using **Layouts**.

A Layout is just a special View that implements the `contracts.Layout` interface by adding a `SetContent(view View)` method.

```go
package components

import "gettako.dev/tako/contracts"

type AppLayout struct {
	content contracts.View
}

func (l *AppLayout) SetContent(view contracts.View) {
	l.content = view
}

func (l *AppLayout) Render(ctx contracts.Context) string {
	header := "=== MY AWESOME APP ==="
	
	var body string
	if l.content != nil {
		body = l.content.Render(ctx)
	}

	return header + "\n\n" + body
}
```

To apply this layout to a group of routes, wrap them in a `Root` closure:

```go
router.Root(&components.AppLayout{}, func() {
	router.Route("/", func() contracts.View { return &components.HomeScreen{} }).Name("home")
	router.Route("/settings", func() contracts.View { return &components.SettingsScreen{} }).Name("settings")
})
```

When you navigate between `home` and `settings`, the `AppLayout` remains completely persistent and is not re-instantiated, allowing you to build complex SPA-like interfaces!

## Route Middleware (Lifecycle Hooks)

Sometimes a View needs to know exactly when it is entering or leaving the screen (for example, to start or stop a background timer, or dispatch a tracking event). 

Your View can optionally implement the `contracts.RouterMiddleware` interface:

```go
type TimerScreen struct {}

func (s *TimerScreen) OnEnter() {
	// Called when the user navigates TO this screen
}

func (s *TimerScreen) OnLeave() {
	// Called when the user navigates AWAY from this screen
}
```
