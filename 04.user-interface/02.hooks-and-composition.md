As your TUI application grows, returning large strings from a single `Render()` method can become difficult to manage. Furthermore, if your application supports third-party plugins, hardcoding child components limits extensibility.

Tako addresses this by providing the `HookManager` to facilitate decoupled UI composition and lifecycle events.

## Composing Components

Let's imagine our Server Dash has a `Dashboard` layout. We want this Dashboard to contain three distinct child components: `Header`, `MetricsCard`, and `Footer`.

Instead of writing all the logic inside a single `Dashboard` struct, we inject the child components and compose their `Render()` methods.

```go
type Dashboard struct {
    header *components.Header
    card   *components.MetricsCard
    footer *components.Footer
}

func NewDashboard() *Dashboard {
    return &Dashboard{
        header: components.NewHeader(),
        card:   components.NewMetricsCard(),
        footer: components.NewFooter(),
    }
}

func (c *Dashboard) Render() string {
    // We compose the final view by concatenating the children
    return c.header.Render() + "\n\n" + c.card.Render() + "\n\n" + c.footer.Render()
}
```

## Bubbling Keyboard Events

If the `Dashboard` is the active route, Tako will call `c.Keys(km)` on it. But what about the child components? If the `MetricsCard` has its own keyboard shortcuts, they won't work automatically because the Router only knows about the parent `Dashboard`.

To solve this, you bubble the `KeyManager` down to your children:

```go
func (c *Dashboard) Keys(km contracts.KeyManager) {
    // Register Dashboard-specific keys
    km.Bind("d", func() { /* Refresh Dashboard */ })

    // Bubble the key manager down to children
    c.header.Keys(km)
    c.card.Keys(km)
    c.footer.Keys(km)
}
```

## Composition via Render Slots (HookManager)

While the manual composition above is sufficient for simple apps, Tako provides a `HookManager` to achieve decoupled UI composition.

Hooks are **named render slots**. A third-party provider or plugin can register a function that returns a UI string for a specific hook name. The main layout retrieves whatever is registered at render time. **Neither side imports the other**—they communicate through the hook namespace.

There are two types of UI Hooks: Single-Slot and Multi-Slot. Tako enforces namespace validation: a hook name is permanently bound to its type (Single or Multi) upon its first registration to prevent collisions.

### Single-Slot Hooks (`Set` / `Get`)

Single-slot hooks model a scenario where there is only one of an item (e.g., a main toolbar or a status bar).

They use **first-wins semantics**. If a plugin tries to `Set` a hook that is already claimed by another, the second attempt is ignored.

**Provider (Plugin) side:**
```go
func (p *MyPlugin) Boot(app contracts.Application) error {
    // Claims the 'ui.statusbar' slot
    app.Hooks().Set("ui.statusbar", func() any {
        return "System Status: Online"
    })
    return nil
}
```

**Layout side:**
```go
func (l *Layout) Render() string {
    // Retrieve the content injected by the plugin
    status := l.app.Hooks().Get("ui.statusbar")
    if status == nil {
        return ""
    }
    return status.(string)
}
```

### Multi-Slot Hooks (`Add` / `All`)

Multi-slot hooks model a scenario where there can be many items (e.g., sidebar navigation links or dashboard widgets).

Multiple providers can `Add` to the same hook name. The layout retrieves `All` of them in the order they were registered.

**Provider (Plugin) side:**
```go
func (p *AnalyticsPlugin) Boot(app contracts.Application) error {
    app.Hooks().Add("ui.sidebar.links", func() any {
        return "[ Analytics ]"
    })
    return nil
}

func (p *SettingsPlugin) Boot(app contracts.Application) error {
    app.Hooks().Add("ui.sidebar.links", func() any {
        return "[ Settings ]"
    })
    return nil
}
```

**Layout side:**
```go
func (l *Sidebar) Render() string {
    // Fetch every registered link
    links := l.app.Hooks().All("ui.sidebar.links")
    
    var output string
    for _, link := range links {
        output += link.(string) + "\n"
    }
    return output
}
```

### Introspection & Management

If you are building developer tools, conditional UIs, or need to debug which slots are active, you can use the built-in introspection methods:

```go
// Returns true if any provider has claimed this slot
exists := app.Hooks().Has("ui.statusbar")

// Returns a sorted list of all active hook names
names := app.Hooks().HookNames() 
// e.g. ["ui.sidebar.links", "ui.statusbar"]

// Returns detailed counts of providers per hook
stats := app.Hooks().HookStats()

// Clears all registered providers for a specific hook
app.Hooks().Clear("ui.statusbar")
```

## Lifecycle Hooks

::note
Lifecycle hooks are distinct from UI Composition Slots. While UI slots return content for rendering, lifecycle hooks execute callbacks when components mount or unmount.
::

Sometimes a component needs to perform an action when it mounts to the screen (like fetching data) or when it unmounts (like cancelling a timer to prevent leaks).

You can use the `HookManager`'s registry to handle this cleanly:

```go
func (c *Dashboard) Init(ctx contracts.Context) {
    ctx.Hooks().OnMount(c.ID(), func() {
        ctx.Logger().Info("Dashboard mounted to screen")
        // Start polling for metrics
    })

    ctx.Hooks().OnUnmount(c.ID(), func() {
        ctx.Logger().Info("Dashboard removed from screen")
        // Stop polling
    })
}
```

By utilizing composition, UI render slots, and lifecycle hooks, you ensure that your codebase remains modular, testable, and extensible.
