When building a traditional terminal application, business logic, state management, and view components often become tightly coupled to the specific rendering library chosen at the beginning. If that library becomes deprecated, you might have to rewrite your entire application.

Tako eliminates this risk by being decoupled from the library responsible for rendering text and capturing inputs. It achieves this abstraction through the **UI Adapter**.

By default, Tako natively ships with an adapter for [Charm's Bubbletea](https://github.com/charmbracelet/bubbletea), a popular choice for modern Go TUI applications.

## What is a UI Adapter?

The `contracts.UIManager` is the interface Tako uses to communicate with the terminal. The adapter translates Tako's concepts (Routes, Components, Keyboard Scopes) into the specific concepts required by the underlying library (e.g., Bubbletea's `tea.Model` and `tea.Msg`).

## Setting the UI Adapter

You set the UI Adapter during the application's bootstrapping phase in your `main.go`:

```go
package main

import (
    "gettako.dev/tako"
    "gettako.dev/tako/pkg/adapter/ui/bubbletea"
)

func main() {
    app := tako.NewApp()

    // Inject the Bubbletea adapter
    app.Mount(bubbletea.New(app))

    tako.Run(app)
}
```

## How the Bubbletea Adapter Works

When you use the Bubbletea adapter, Tako acts as the core framework while Bubbletea handles rendering.

1. **The Framework:** Tako handles State, Routing, Events, Dependency Injection, and Middlewares.
2. **The Handshake:** When the user navigates to a new route, Tako's Router injects the active Component into the adapter.
3. **The Wrapper:** The Adapter wraps your component inside an internal `tea.Model`.
4. **The Render:** When `Render()` is called on your component, the Adapter takes the returned string and hands it to Bubbletea to draw on the screen.
5. **The Input:** When a user presses a key, Bubbletea captures it and passes it back to Tako's Input Manager.

## The Power of the Abstraction

Because of this abstraction layer:
- Your UI Components (`contracts.Component`) do not import `"github.com/charmbracelet/bubbletea"`. They return a testable string from `Render()`.
- If a different rendering library is used in the future, you swap out the adapter mount in `main.go` and none of your application logic or UI components will need to be rewritten.

::note
While your components do not import Bubbletea, you can use [Lipgloss](https://github.com/charmbracelet/lipgloss) for styling the strings returned by your `Render()` methods. It is a pure string-manipulation library that complements Tako's decoupled architecture.
::
