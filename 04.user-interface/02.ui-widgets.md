One of the design goals of Tako is to dramatically simplify the Developer Experience of building TUI applications. 

In vanilla Bubble Tea, every single component must implement `Init()`, `Update()`, and `View()`. Tako abstracts this away, requiring only a `Render()` method for standard Views, and handling inputs elegantly via the [Mouse & Keyboard Managers](/input-handling/keyboard).

## Why do we need the MessageHandler?

If Tako abstracts away the `Update(msg)` loop, how do we use complex, interactive native Bubble Tea components (like `textinput`, `table`, or `spinner`)? 

These third-party components were built strictly for the vanilla Bubble Tea architecture. They internally rely on receiving raw `tea.Msg` events (like `tea.KeyMsg` for typing characters, or timer events for blinking cursors and spinning animations). Without these raw messages, a `textinput` won't know when you type a letter!

To bridge this gap, Tako provides the **`contracts.MessageHandler`** interface. By implementing this interface, your Tako View opts back in to receiving the raw, unfiltered message stream, which you can then pass down to your native widgets.

## Example: Integrating `textinput`

Let's build a screen that asks for the user's name using the official `github.com/charmbracelet/bubbles/textinput` widget.

### 1. Initialize the Widget

First, define your struct and initialize the native component, usually in a factory function.

```go
package components

import (
	"github.com/charmbracelet/bubbles/textinput"
	"gettako.dev/tako/contracts"
)

type FormScreen struct {
	input textinput.Model
}

func NewFormScreen() *FormScreen {
	ti := textinput.New()
	ti.Placeholder = "Enter your name..."
	ti.Focus() // Set focus so the cursor blinks

	return &FormScreen{
		input: ti,
	}
}
```

### 2. Implement the MessageHandler

Next, implement the `Update(msg any) bool` method from `contracts.MessageHandler`. This is where the magic happens: we catch the raw `tea.Msg` and feed it directly into the native widget's own `Update` function.

```go
// Implement contracts.MessageHandler
func (s *FormScreen) Update(msg any) bool {
	var cmd tea.Cmd
	
	// Pass the message to the native widget
	s.input, cmd = s.input.Update(msg)
	
	// Note: In Tako v2, the framework handles the internal Command dispatching automatically
	// if you were to return it, but for simple state updates, just updating the model is enough.
	
	// Return true to stop propagation, or false to let other handlers process this message
	return false
}
```

### 3. Render the Widget

Finally, simply call the native widget's `View()` method inside your Tako `Render` string.

```go
func (s *FormScreen) Render(ctx contracts.Context) string {
	return "What is your name?\n\n" + s.input.View()
}
```

## Conclusion

By implementing `MessageHandler`, Tako gives you the best of both worlds:
- For 90% of your application (static text, layouts, menus, buttons), you enjoy Tako's clean `Render`-only Views and elegant Event/Input Managers.
- For the 10% of complex, highly interactive data-entry fields, you can seamlessly drop down into native Bubble Tea components without sacrificing architecture.
