The `DialogService` provides `Confirm(message, callback)`. It's a single method that pushes a confirmation overlay onto the stack, registers ephemeral `y/n` keybindings, waits for
the user's response, invokes your callback, and closes the overlay — all handled atomically by the framework.

## The Confirm Call

```go [providers/orders/provider.go]
func (p *OrderProvider) confirmDelete(ctx *tako.Context, orderID string) {
    // Non-blocking: pushes overlay and returns immediately.
    // The callback fires later when the user presses y, n, enter, or esc.
    ctx.UI().Dialog().Confirm(
        fmt.Sprintf("Delete order %s? This cannot be undone.", orderID),
        func(yes bool) {
            if yes {
                p.deleteOrder(orderID)
                ctx.Emit("order:deleted", orderID)
            }
        },
    )
}
```

The callback executes exactly once, guarded by a `sync.Once`.

## Keybindings and Events

When a dialog is active, it traps all input at its stack level. Unbound keys are ignored.

| Key          | Action  | Callback Arg | Event Emitted      |
|--------------|---------|--------------|--------------------|
| `y`, `Enter` | Confirm | `true`       | `dialog:confirmed` |
| `n`, `Esc`   | Cancel  | `false`      | `dialog:cancelled` |

You can subscribe to these events globally for analytics:

```go [providers/analytics/provider.go]
func (p *AnalyticsProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()
    app.Events().Subscribe(ctx.Context, "dialog:confirmed", func(e contracts.Event) { p.track("dialog_accept") })
    app.Events().Subscribe(ctx.Context, "dialog:cancelled", func(e contracts.Event) { p.track("dialog_cancel") })
    return nil
}
```

## Rendering the Dialog

The dialog service exposes its state via the `"tako.overlay.tako.dialog.confirm"` hook. Your layout decides how it looks:

```go [layouts/base.go]
func (l *Base) View(ctx *tako.Context) tea.View {
    // ... render base layout ...

    if r.Stack().Top() == "tako.dialog.confirm" {
        dialogMsg := ctx.Hooks().Get("tako.overlay.tako.dialog.confirm")
        if dialogMsg != nil {
            // Layout dictates the styling (centered box, slide-in banner, etc.)
            styled := l.dialogStyle.Render(
                fmt.Sprintf("%s\n\n[y/enter] Confirm   [n/esc] Cancel", dialogMsg),
            )
            // Overlay it on top of the base view
            return applyOverlay(baseView, styled)
        }
    }

    // ...
}
```

The data structure is decoupled from presentation. The service provides the message string; the layout provides the pixels.

::warning
Only one confirm dialog can be active at a time. If you call `Confirm` while a dialog is already showing, the previous dialog is cancelled (its callback fires with `false`), and
the new one replaces it.
::

::tip
If you need custom dialogs (e.g. text input prompts, multi-choice menus), build them as standard [Components](/components/component-interface) that take a callback function in
their constructor. The built-in `DialogService` is intentionally kept simple for the 90% use case of boolean confirmations.
::
