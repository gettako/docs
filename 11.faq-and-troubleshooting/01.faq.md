## General

### What is Tako?

Tako is a robust, contract-first Go framework for building Terminal User Interfaces (TUIs) and CLI applications. It is built heavily on top of the beloved [Bubble Tea](https://github.com/charmbracelet/bubbletea) library, but introduces enterprise-grade architecture like a Service Container, Event Bus, and Routing system.

### Why not just use vanilla Bubble Tea?

Bubble Tea is a fantastic, unopinionated library for building terminal apps using The Elm Architecture. However, as your application grows into a massive multi-screen SPA (Single Page Application), passing state manually up and down a giant component tree becomes tedious. 

Tako provides the "missing framework layer" (routing, dependency injection, events, configuration) so you can focus on building your app rather than reinventing the wheel. If you love Laravel or Angular's architecture, you will feel right at home with Tako.

## Architecture

### Why does Tako use `contracts.View` instead of `tea.Model`?

Tako wraps `tea.Model` with `contracts.View` to dramatically simplify the Developer Experience. In vanilla Bubble Tea, every single component must implement `Init()`, `Update()`, and `View()`, even if it's just a static piece of text. 

In Tako, a View only strictly requires `Render()`. Interactions (Input, Mouse, raw Messages) are fully opt-in via optional interfaces like `contracts.KeyBinder`.

### Can I use existing Bubble Tea components?

Absolutely! Tako doesn't reinvent rendering. Any component from `bubbles` (like `textinput`, `spinner`, or `table`) can be embedded directly into a Tako View. You simply implement the `contracts.MessageHandler` interface to pass raw `tea.Msg` events down to the native Bubble Tea component.

### Is the Service Container thread-safe?

Yes. Tako's internal `Container` uses `sync.RWMutex` to ensure that reading and writing bindings across multiple goroutines or asynchronous CLI commands is completely safe.

## Performance

### Will the Event Bus cause memory leaks?

No, but only if you use it correctly! The Tako Event Bus is highly optimized using an O(1) swap-remove algorithm for canceling listeners. When you register a listener using `app.Events().Listen()`, it returns a `cancel` function. You **must** call this cancel function when your UI component is destroyed (using `OnLeave` middleware) to prevent memory leaks.

### How big is the compiled binary?

Because Tako is written in pure Go and relies on lightweight dependencies, the compiled binary is extremely small, typically under 10MB statically linked, making it incredibly fast to boot and deploy.
