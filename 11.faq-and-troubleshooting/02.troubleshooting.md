If you run into issues while building your Tako application, don't panic! Here are the most common pitfalls and how to solve them.

## Dependency Injection Errors

### `dependency 'X' is not registered`

This is the most common error you will encounter when using the Service Container.

**Cause:** You are trying to resolve a service using `app.Make()` or `contracts.Resolve()` before it has been bound to the container.
**Solution:** Check your Service Providers. Make sure the provider that registers the service is actually added to `app.Register()` in your `main.go` file. Also, ensure you are
resolving the service in the `Boot` phase, not the `Register` phase.

### `dependency 'X' does not match requested type`

**Cause:** You bound a service as one type (e.g., `*sql.DB`) but are attempting to resolve it as a different type (e.g., `sql.DB` without the pointer) using `contracts.Resolve[T]`.
**Solution:** Ensure the generic type signature exactly matches what the factory function returned during `app.Singleton()` or `app.Bind()`.

## Routing & UI Errors

### Screen is completely blank

**Cause:** If you run your application and see absolutely nothing (just a blank terminal), you likely forgot to navigate to an initial route, or your default route's `Render`
method is returning an empty string.
**Solution:** Ensure you call `router.Navigate("your_route_name")` inside your `main.go` before calling `tako.Run(app)`.

### Stale state when returning to a screen

**Cause:** You registered a route by passing a pointer to an existing struct, rather than using a factory function.

```go
// ❌ WRONG: This shares the exact same instance every time!
screen := &components.SettingsScreen{}
router.Route("/settings", func() contracts.View { return screen })

// ✅ CORRECT: Creates a fresh instance every time
router.Route("/settings", func() contracts.View { return &components.SettingsScreen{} })
```

### Mouse clicks aren't working

**Cause:** You used `zone.Mark()` in your `Render` method, but didn't implement `contracts.ActionHandler` on your component, or you didn't register the listener.
**Solution:** Ensure you embed `view.BaseComponent` (which automatically implements `contracts.ActionHandler`) or manually implement `HandleMouseAction` to process the clicks on
your zones.

## Logging

### I don't see any logs in the terminal

**Cause:** By design, Tako does not write logs to `stdout` because doing so would completely break the Bubble Tea terminal layout.
**Solution:** Check your storage directory. In development, logs are written to `.tako/tako.log` by default. You can read them in real-time by opening a separate terminal window
and running:

```bash
tail -f .tako/tako.log
```
