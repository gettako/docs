# Service Providers

In Tako, **everything is a Service Provider**. Your database connection, your router, your UI components, your third-party plugins — all are providers. This unified model keeps the
framework simple and your code testable.

A provider answers two questions:

1. **What do you offer?** → `Register` (bind services to the container)
2. **What do you do?** → `Boot` (execute logic once everything is ready)

## The Interface

```go
type ServiceProvider interface {
    Register(app *Application) error
    Boot(app *Application) error
}
```

Two methods. No implicit behavior. No annotations. No config files.

## Quick Example

```go
type GreetingProvider struct{}

func (p *GreetingProvider) Register(app *foundation.Application) error {
    app.Container().Singleton("greeting", "Hello, Tako!")
    return nil
}

func (p *GreetingProvider) Boot(app *foundation.Application) error {
    app.Logger().Info("Application ready")
    return nil
}
```

## Registration

Providers are registered **explicitly** in `main.go`. No `init()` implicit behavior, no auto-discovery:

```go
func main() {
    app := tako.NewApp()

    app.RegisterProviders(
        &providers.DatabaseProvider{},
        &providers.RouterProvider{},
        &providers.UIProvider{},
    )

    tako.Run(app)
}
```

**Order matters.** Providers register and boot in the order you list them. This is explicit, visible, and easy to reason about.

## Two-Phase Guarantee

```
Register A → Register B → Register C → Boot A → Boot B → Boot C
```

All `Register` calls complete before any `Boot` runs. During `Boot`, every service is guaranteed available in the container.

## Dynamic Registration

Providers can register sub-providers:

```go
func (p *EcommerceProvider) Register(app *foundation.Application) error {
    return app.RegisterProviders(
        &CartProvider{},
        &CheckoutProvider{},
    )
}
```
