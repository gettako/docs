Service Providers connect the Tako Framework to your application's custom features. They provide a dedicated place to set up databases, background jobs, or third-party libraries before your UI starts rendering.

Every core feature in Tako (such as the Router, UI Manager, Logger, and Event Bus) is bootstrapped via a Service Provider.

## Anatomy of a Service Provider

A Service Provider is a struct that implements the `contracts.ServiceProvider` interface. It requires two methods: `Register` and `Boot`.

```go
type ServiceProvider interface {
    Register(app Application) error
    Boot(app Application) error
}
```

### The Register Phase
Tako calls the `Register` method first on all registered providers. 

**Rule of thumb:** Only bind services into the `app.Container()` here. Do not attempt to resolve other services (like the Logger or Database) because their respective providers might not be registered yet.

### The Boot Phase
Tako calls the `Boot` method after all providers have finished their `Register` phase. 

**Rule of thumb:** Here you can safely resolve dependencies using `app.Make()` and perform initialization logic (e.g., subscribing to events, registering global middlewares, running database migrations).

## Creating a Provider

Let's create a `DatabaseProvider` for our Server Dash application.

```go [internal/providers/database.go]
package providers

import (
    "gettako.dev/tako/contracts"
)

type DatabaseProvider struct{}

func (p *DatabaseProvider) Register(app contracts.Application) error {
    // Bind the database connection lazily into the IoC container
    app.Container().Lazy(new(contracts.Database), func() (any, error) {
        return ConnectToDatabase("sqlite://serverdash.db")
    })
    
    return nil
}

func (p *DatabaseProvider) Boot(app contracts.Application) error {
    // Resolve the logger and database safely here since all providers are registered
    var logger contracts.Logger
    var db contracts.Database

    app.Make(&logger)
    app.Make(&db)

    logger.Info("Database provider booted.")
    
    // Trigger a migration
    db.Migrate()

    return nil
}
```

## Registering Providers

To make Tako aware of your new provider, you must register it when initializing your application in `main.go`. You can use the `app.Providers()` method:

```go [main.go]
package main

import (
    "fmt"
    "os"
    
    "gettako.dev/tako"
    "github.com/yourusername/server-dash/internal/providers"
)

func main() {
    app := tako.NewApp()

    // Register our custom providers
    err := app.Providers(
        &providers.DatabaseProvider{},
        &providers.MetricsProvider{},
    )
    if err != nil {
        fmt.Printf("Failed to register providers: %v\n", err)
        os.Exit(1)
    }

    // Run the application
    if err := tako.Run(app); err != nil {
        fmt.Printf("Application crashed: %v\n", err)
        os.Exit(1)
    }
}
```

## Disposable Providers

If your provider initializes a service that requires cleanup (like closing a database connection or stopping a background goroutine), you can implement the `contracts.Disposable` interface by adding a `Shutdown` method to your struct.

```go
func (p *DatabaseProvider) Shutdown(app contracts.Application) error {
    var db contracts.Database
    if err := app.Make(&db); err == nil {
        return db.Close()
    }
    return nil
}
```

When the user quits the application or the context is cancelled, Tako calls `Shutdown` on all disposable providers in the reverse order of their registration (LIFO).

::tip
Use Disposable Providers to handle cleanups. Relying on `defer` inside your `main` function will not work effectively if background services are spawned in other files or if the application exits abruptly.
::
