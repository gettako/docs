The Tako Service Container is the heart of the framework. If you only learn one concept in Tako, make sure it is this one!

At its core, the container is a powerful tool for managing class dependencies, abstracting interfaces, and completely replacing mutable global state. It allows you to build highly decoupled, testable, and robust terminal applications.

## Why do we need a Container?

In standard Go applications, you might pass dependencies (like database connections or loggers) directly into your structs, or even worse, store them as global variables.

```go
// The messy way: passing dependencies manually
userRepo := NewUserRepository(dbConnection)
userController := NewUserController(userRepo, logger, config)
```

In Tako, everything is resolved automatically from the container when you need it.

## Binding Services

Binding simply means telling the container *how* to construct a dependency. You usually perform bindings inside the `Register` method of your [Service Providers](/architecture-concepts/providers).

### Singletons

The most common way to bind a service is as a **Singleton**. When you bind a singleton, the container will execute your closure exactly *once*. Every subsequent time you ask the container for this service, it will return the exact same instance.

```go
app.Singleton("database", func(c contracts.Container) any {
    return ConnectDatabase()
})
```

### Instances

If you already have a live object and just want to insert it directly into the container, you can use the `Instance` method.

```go
db := ConnectDatabase()
app.Instance("database", db)
```

### Transients (Bind)

If you need a completely fresh, newly constructed instance every single time you ask for the service, use the `Bind` method.

```go
app.Bind("random-id-generator", func(c contracts.Container) any {
    return GenerateUUID()
})
```

### Aliases

You can also assign aliases to existing bindings. This is useful if you want to provide a short name for a long, fully qualified service name.

```go
app.Alias("db", "database.connection.mysql")
```

## Resolving Dependencies

There are multiple ways to extract a service out of the container. 

### The `Make` method

The most direct way is using the `Make` method. However, `Make` returns `any`, which means you will have to type-assert it yourself.

```go
val := app.Make("database")
db := val.(*sql.DB)
```

### The `contracts.Resolve` Helper (Recommended)

To make resolution safer and completely type-safe without messy type assertions, Tako provides a generic `contracts.Resolve[T]` helper.

```go
import "gettako.dev/tako/contracts"

db, err := contracts.Resolve[*sql.DB](app, "database")
if err != nil {
    panic(err)
}
```

This ensures that the returned dependency is exactly the type you expect. If it isn't, or if the service doesn't exist, it gracefully returns an error.

## Zero Global State

Because the Service Container is passed around (or injected) where needed, Tako completely eliminates the need for mutable global variables in your application.

Your application instance (`app`) is completely thread-safe, making it perfectly fine to read bindings from background goroutines or concurrent TUI commands!
