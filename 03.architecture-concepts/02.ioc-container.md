Manually instantiating structs and passing them down through multiple layers of your application can lead to tightly coupled code. Testing becomes difficult when components are tied to concrete implementations.

Tako addresses this with an Inversion of Control (IoC) Container. Instead of manually managing dependencies, the container resolves and injects the dependencies you request.

## Binding Dependencies

The container supports three types of bindings: **Singleton**, **Lazy**, and **Transient**.

### 1. Singleton Binding
A Singleton binding guarantees that a dependency is instantiated only once. Every subsequent time you ask the container for this dependency, it returns the same instance.

You can bind a singleton directly on the application instance:

```go
app.Singleton(new(contracts.Database), &MySQLDatabase{})
```

### 2. Lazy Binding
A Lazy binding behaves like a Singleton, but its initialization is deferred until the dependency is requested for the first time. This is useful for optimizing boot times and memory usage.

```go
app.Container().Lazy(new(contracts.Storage), func() (any, error) {
    // This closure remains dormant until contracts.Storage is requested
    return InitCloudStorage()
})
```

### 3. Transient Binding
A Transient binding executes a factory function every time it is resolved. It returns a new instance on every request.

You can bind it on the application instance:

```go
app.Transient(new(contracts.QueryBuilder), func() (any, error) {
    return NewQueryBuilder(), nil
})
```

## Resolving Dependencies

Once your dependencies are bound into the container, resolving them is straightforward.

### Using `Make`
You can resolve a dependency using the `Make()` shortcut by passing a pointer to a variable that implements the interface.

```go
var db contracts.Database
err := app.Make(&db)

if err == nil {
    db.Query("SELECT * FROM users")
}
```

### Using `Call` (Auto-Injection)
The `Call()` method executes a given function and automatically injects its parameters based on the function's signature.

```go
// The container looks at the parameters and injects them automatically
err := app.Call(func(logger contracts.Logger, db contracts.Database) {
    logger.Info("Executing auto-injected function")
    db.Ping()
})
```

::warning
Dependency Injection is most effective when you bind against interfaces, not concrete structs. Try to bind your implementations to the abstract definitions in the `contracts/` directory. This ensures you can swap out drivers later without breaking your application code.
::

## The Container in Server Dash

In our Server Dash application, we might need a `MetricsFetcher` service. Instead of instantiating it globally, we bind it to the container inside a Service Provider. This means any UI component can request it without knowing how it was built, keeping our domains decoupled and easier to mock for testing.
