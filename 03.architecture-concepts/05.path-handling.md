When building applications, you often need to read or write files (such as SQLite databases, log files, cache files, or user uploads). 

A common mistake developers make is hardcoding relative paths:

```go
// ❌ WRONG: Do not do this!
file, err := os.Create("./storage/database.sqlite")
```

## Why Hardcoding Fails

Hardcoding `./storage` might work perfectly on your local machine while developing. However, when you compile your application into a single binary and distribute it to users, this breaks immediately. 

If a user executes your binary from their `~/Downloads` folder, the application will try to create a `storage` folder directly inside `~/Downloads`. If they run it from `/usr/bin/`, it might crash due to missing write permissions!

## The Virtual Home Folder

To solve this, Tako implements a highly intelligent **Virtual Home Folder** architecture, managed by the `contracts.AppPath` interface. Tako automatically resolves paths based on your application's current environment (`app.env`):

### Development Mode (`local` or `development`)
When you are actively coding (`go run main.go`), Tako isolates all storage into a hidden `.tako/` directory relative to your project root. This keeps your git repository clean while keeping the files easy to inspect.

### Production Mode (`production`)
When compiled and deployed, Tako completely abandons the local directory and instead creates a Virtual Home Folder in the user's OS-level home directory, prefixed with a dot and your application name. For example: `~/.my-app/`.

This ensures that your application data (logs, databases, config overrides) persists safely across binary updates, and avoids polluting the directory where the binary happens to be executed.

## Using the Path API

You can access the Path manager directly from the application context `ctx.App().Path()`, or via dependency injection by resolving `contracts.AppPath`.

The Path API provides several helper methods to resolve absolute paths intelligently:

### `Storage()`
Returns the root of the Virtual Home Folder. Use this for SQLite databases or long-term caching.
```go
// Dev:  /path/to/project/.tako
// Prod: /Users/username/.my-app
dbPath := filepath.Join(app.Path().Storage(), "database.sqlite")
```

### `Run()`
Returns the directory used for volatile runtime files, such as PID files or Unix sockets (used by the Profiler).
```go
// Dev:  /path/to/project/.tako/run
// Prod: /Users/username/.my-app/run
sockPath := filepath.Join(app.Path().Run(), "12345.sock")
```

### `Log()`
Returns the directory specifically designated for application log files.
```go
// Dev:  /path/to/project/.tako/logs
// Prod: /Users/username/.my-app/logs
logPath := filepath.Join(app.Path().Log(), "tako.log")
```

By strictly using the `AppPath` contract, your application will seamlessly transition from a local development environment into a globally installed CLI tool without a single line of code changing!
