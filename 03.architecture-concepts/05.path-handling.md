Terminal applications often need a safe location to write log files, caches, and local databases without polluting the user's system or committing them to a Git repository.

Tako handles this with a dual-dimension path architecture.

## The Two Dimensions

Tako shifts its internal storage paths depending on whether you are developing the application or running it as a compiled binary.

### 1. Dev Mode (`.tako/`)
When you run your application during development (e.g., using `go run main.go`), Tako detects that it is running inside a Go workspace. 

It automatically creates a hidden `.tako/` directory at the root of your project. This acts as a sandboxed runtime environment.
- Logs go to `.tako/storage/logs/`
- Caches go to `.tako/storage/framework/cache/`
- Local databases go to `.tako/database/`

::tip
You should add `.tako/` to your `.gitignore` file. This prevents temporary caches and debug logs from being committed to your repository.
::

### 2. Prod Mode (`~/.app-name/`)
When you build your application and run the compiled binary on a user's machine, Tako shifts the root storage path to comply with standard OS data practices.

It will use the user's home directory (or standard OS app-data directory) based on the application's configured name. For example, if your app is named `server-dash`:
- Linux/macOS: `~/.server-dash/`
- Windows: `%APPDATA%\server-dash\`

You can also override this root path by setting the `TAKO_DATA_DIR` environment variable before launching the binary.

## 1. Base Project Structure

At the root of your workspace, you define your application's default resources:

```text
<project-root>/
├── config/              # Default configuration files
├── lang/                # Default translation dictionaries
├── themes/              # Default UI themes
└── .tako/               # (Git ignored) Dynamic storage for dev mode
```

When building your application for production, the `config/`, `lang/`, and `themes/` directories are typically embedded directly into the binary using Go's `go:embed` directive. This ensures your application ships with all necessary default resources.

## 2. Dynamic Storage (Overrides & Data)

While the Base Project contains your defaults, Tako uses the dynamic storage paths (`.tako/` in Dev Mode or `~/.app-name/` in Prod Mode) as a virtual user directory.

The internal folder structure inside this dynamic storage remains identical in both modes:

```text
(Dynamic Root: .tako/ OR ~/.app-name/)
├── storage/
│   ├── framework/
│   │   ├── cache/       # Used by the Cache manager
│   │   └── views/       # Compiled templates (if applicable)
│   └── logs/            # Rolling application log files
├── database/            # Local databases (SQLite, BoltDB)
├── config/              # High-priority user config overrides
├── lang/                # High-priority translation overrides
└── themes/              # High-priority user theme overrides
```

Any files placed in the dynamic `config/`, `lang/`, or `themes/` folders will automatically **override** the default embedded files from the Base Project.

## Resolving Paths in Code

You should not hardcode file paths in your service providers or business logic. Tako provides path resolution methods on the `Application` interface to ensure you target the correct directory dynamically.

```go
func (p *MyDatabaseProvider) Boot(app contracts.Application) error {
    // This resolves to the Base Project (e.g. for embedded defaults)
    defaultTheme := app.BasePath("themes", "dracula.yml")
    
    // This dynamically resolves to the override/data path:
    // Dev: `.tako/database/data.db` 
    // Prod: `~/.server-dash/database/data.db`
    dbPath := app.StoragePath("database", "data.db")
    
    // You can also get other base paths directly:
    storageRoot := app.StoragePath("framework", "cache")
    configRoot := app.ConfigPath("logging.yml")

    return nil
}
```

::warning
If you use hardcoded relative paths like `./database.db`, your application will write files to the directory the user is currently in when they execute your binary. This can lead to permission errors or lost data.
::
