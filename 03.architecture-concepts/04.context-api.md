While the IoC Container is powerful, writing `app.Make(&logger)` every time you need to log a message can become verbose. 

To address this, Tako provides the **Context API** (`contracts.Context`) as an accessor hub. If you have used web frameworks like Echo or Fiber, this `Context` pattern will feel familiar.

## What is the Context?

The `Context` acts as a lightweight facade over the underlying `Application` and its IoC Container. It exposes direct, strictly-typed methods to access the framework's most frequently used managers and services.

Whenever you are inside a Middleware, an Event Handler, a Command, or a UI Component, you will typically receive or have access to a `contracts.Context`.

## Accessing Services

Here is how you can utilize the Context API in your code:

```go
func HandleRequest(ctx contracts.Context) {
    // 1. UI & Rendering
    ctx.UI().RequestRender() // Signal the adapter that the UI needs a redraw
    
    // 2. Routing
    ctx.Router().GoTo("dashboard")

    // 3. Events
    ctx.Events().Dispatch("user.login").WithPayload(user).Fire()

    // 4. Logging
    ctx.Logger().Info("Request handled successfully")

    // 5. Global State
    ctx.State().Mutate("session_id").Value("xyz-123").Broadcast()

    // 6. Configuration
    debug := ctx.Config().Get("app.debug", false).Bool()
}
```

## Why use Context instead of Global Variables?

By routing service access through the `Context`, Tako provides three architectural benefits:
1. **Thread Safety:** The Context itself is lightweight and safe to pass across multiple goroutines.
2. **Mockability:** You can mock the `Context` interface in your unit tests without needing to instantiate a real application, router, or database.
3. **No Hidden State:** You avoid memory leaks and hidden dependencies. If a function needs to trigger an event, its signature explicitly demands the `Context`, making your code predictable.
