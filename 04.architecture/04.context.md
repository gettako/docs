The Tako Context wraps Go's standard `context.Context` and the service container, layering a rich set of cached accessors and fluent helpers on top. Every provider, every command,
and every lifecycle hook uses one — through it, you access every service the framework provides without manual container resolution or error handling.

## Service Accessors

Every accessor on `*tako.Context` uses a fast-path/slow-path pattern with `sync.RWMutex`. After the first call, subsequent calls are essentially free — a read-locked field access,
not a container lookup.

| Accessor        | Returns                  | Use For                                        |
|-----------------|--------------------------|------------------------------------------------|
| `ctx.Logger()`  | `contracts.Logger`       | Structured logging (Warn, Info, Error, Debug)  |
| `ctx.Config()`  | `contracts.Config`       | Reading app configuration by dot-notation key  |
| `ctx.Events()`  | `contracts.EventBus`     | Full bus API (Emit, On, Subscribers, etc.)     |
| `ctx.State()`   | `contracts.StateManager` | In-memory reactive key-value store             |
| `ctx.Storage()` | `contracts.KVStore`      | Persistent key-value store (survives restarts) |
| `ctx.Hooks()`   | `contracts.HookRegistry` | Render-slot providers and consumers            |
| `ctx.Theme()`   | `contracts.ThemeManager` | Color token resolution per active theme        |
| `ctx.Lang()`    | `contracts.LangManager`  | Translation string resolution                  |
| `ctx.Jobs()`    | `contracts.Scheduler`    | Background jobs and recurring tasks            |
| `ctx.Router()`  | `contracts.Router`       | Focus stack and input routing engine           |
| `ctx.UI()`      | `contracts.UIManager`    | Modal dialogs and overlay panels               |
| `ctx.RPC()`     | `contracts.RPCBus`       | Synchronous inter-provider request-response    |

```go [providers/orders/provider.go]
func (p *OrderProvider) Boot(app *foundation.Application) error {
    // Access any service — no error handling, no resolution ceremony
    app.Logger().Info("Order provider initializing")
    app.State().Mutate("orders:active_count").Value(0).Broadcast()

    p.client = &APIClient{
        BaseURL: app.Config().String("api.base_url", "http://localhost:8080"),
        Timeout: time.Duration(app.Config().Int("api.timeout", 10)) * time.Second,
    }

    app.RPC().Route("orders:active_count").
        Handle(func(req contracts.RPCRequest) contracts.RPCResponse {
            return contracts.RPCResponse{Data: app.State().Mutate("orders:active_count").Get()}
        })
    return nil
}
```

## Fluent Event Helpers

Direct methods on the context cover the four core subscription patterns:

```go [providers/notifications/provider.go]
func (p *NotificationProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()

    // Emit — publish an event; all handlers run before this returns
    ctx.Emit("notification:initialized", nil)

    // Subscribe — context-aware, auto-cleaned when provider is destroyed
    app.Events().Subscribe(ctx.Context, "order:completed", func(e contracts.Event) {
        order := e.Data.(*Order)
        p.showBadge("Order " + order.ID + " completed")
    })

    // Once — fires exactly once, then removes itself automatically
    ctx.Once("app:ready", func(e contracts.Event) {
        p.loadUnreadFromStorage()
    })

    // On — persists until the returned cancel function is called
    cancel := ctx.On("debug:dump_state", func(e contracts.Event) {
        app.Logger().Debug("notifications state", "queue", p.queue)
    })

    // Call cancel() if you need to stop this before shutdown
    p.cancelDebugSub = cancel
    return nil
}
```

**Choose by lifecycle scope:**

| Method          | Lives Until                       | Use When                                    |
|-----------------|-----------------------------------|---------------------------------------------|
| `ctx.Subscribe` | Context cancelled                 | Provider-scoped handlers (most common)      |
| `ctx.Once`      | First fire (or context cancelled) | One-time initialization signals             |
| `ctx.On`        | Explicitly cancelled              | Truly global, application-lifetime handlers |

## Input Registration

```go [providers/search/provider.go]
func (p *SearchProvider) Boot(app *foundation.Application) error {
    ctx := app.Context()

    // Global key — fires from any focus state
    ctx.Keys().Bind("ctrl+f", p.openSearch)

    // Zone-scoped key — fires only when "results" zone is focused at level 1
    ctx.Keys().Zone("results", 1).Bind("enter", p.selectResult)
    ctx.Keys().Zone("results", 1).Bind("esc", p.closeSearch)

    // Mouse handler — fires when the "results" zone is clicked
    ctx.Mouse().Zone("results").OnClick(func(x, y int) {
        p.selectItemAt(y)
    })
    ctx.Mouse().Zone("results").OnScrollDown(func(x, y int) {
        p.scrollDown()
    })
    return nil
}
```

## Background Work

### ctx.Spawn

Goroutines launched with `Spawn` are tracked by the Context's internal wait group. `ExecuteCleanup` waits for all spawned goroutines before the process exits. Always select on
`innerCtx.Done()` — if you don't, shutdown will hang.

```go [provider.go]
func (p *SyncProvider) Boot(app *foundation.Application) error {
    app.Spawn(func(innerCtx context.Context) {
        ticker := time.NewTicker(30 * time.Second)
        defer ticker.Stop()

        for {
            select {
            case <-innerCtx.Done():
                return // Shutdown signal received
            case <-ticker.C:
                p.sync(app.Context())
            }
        }
    })
    return nil
}
```

### ctx.OnDestroy

Register inline cleanup callbacks — co-located with resource acquisition:

```go [provider.go]
func (p *Provider) Boot(app *foundation.Application) error {
    conn, err := openConnection(app.Config().String("service.endpoint"))
    if err != nil {
        app.Logger().Error("connection failed", "err", err)
        return err
    }

    // Cleanup lives next to the resource it cleans up — easy to audit
    app.OnDestroy(func() {
        app.Logger().Info("Closing service connection")
        conn.Unmount()
    })

    p.conn = conn
    return nil
}
```

Multiple `OnDestroy` callbacks execute in LIFO (last-in-first-out) order during shutdown.

## Child Contexts

`Derive` creates a child context with its own cancellation scope, sharing the parent's container:

```go [provider.go]
func (p *Provider) handleExport(ctx *tako.Context, format string) {
    // Child context is cancelled when cancel() is called,
    // or automatically when the parent shuts down
    childCtx, cancel := ctx.Derive()
    defer cancel()

    childCtx.Spawn(func(innerCtx context.Context) {
        p.runExport(innerCtx, format)
    })
}
```

Use child contexts to scope work to a specific user interaction or operation. When the operation completes, `cancel()` cleans up spawned goroutines and registered `OnDestroy`
callbacks without affecting the parent.

## Shared Context Model

The application-level context and provider contexts are the same object — same instance, same container, same cancellation. Services resolved in `main.go` are available to all
providers; events emitted in one provider are received by another.

```go [main.go]
app := tako.NewApp()
rootCtx := app.Context()

// This logger is the same instance any provider receives via app.Logger()
rootCtx.Logger().Info("Application created")
```

::tip
Never resolve the same service multiple times in a hot path. `app.Logger()` on every call is fine (cached after the first), but if you resolve a service via `container.Make()` in a
render loop, you'll pay the reflection cost every frame. Assign resolved services to provider struct fields during `Boot` and reference those fields in render methods.
::
