Terminal applications often need to perform recurring tasks—like polling a REST API for metrics, saving state to disk every minute, or cleaning up old logs. 

Developers usually attempt to solve this by spawning a manual `go func()` with an infinite `time.Ticker` loop. Unfortunately, this can lead to memory leaks, race conditions, and applications that refuse to shut down cleanly because a cancellation context was not passed properly.

Tako addresses this by providing a built-in `Scheduler` manager (`contracts.Scheduler`) that makes registering managed background jobs simple.

## Registering Scheduled Jobs (Cron & Intervals)

You interact with the Scheduler through the Application instance or the Context API (`app.Jobs()` or `ctx.Jobs()`).

For recurring tasks at a specific interval:
```go
stop := ctx.Jobs().Every(10 * time.Second, func() {
    ctx.Logger().Info("Running metrics collection...")
})
// You can call stop() later to manually cancel this interval
```

For tasks following a Cron expression:
```go
stop, err := ctx.Jobs().Cron("*/5 * * * *", func() {
    ctx.Logger().Info("Running cron job every 5 minutes...")
})
```

## Advanced Background Jobs (Dispatching)

For one-off background jobs or tasks that require high reliability, use `Dispatch()`. The `Dispatch()` method returns a fluent `JobBuilder` API that supports delayed execution, automatic retries, and overlap prevention.

```go
ctx.Jobs().Dispatch(func(jobCtx context.Context) (any, error) {
    // Simulate an expensive network call
    req, _ := http.NewRequestWithContext(jobCtx, "GET", "https://api.example.com", nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return nil, err // Returning an error triggers a retry or OnError
    }
    defer resp.Body.Close()
    
    return "success", nil
}).
    WithName("fetch-metrics").
    WithoutOverlapping().           // Skip if the previous instance is still running
    Retries(3).                     // Auto-retry up to 3 times on failure
    RetryDelay(5 * time.Second).    // Wait 5 seconds between retries
    Delay(1 * time.Minute).         // Delay the start of the job by 1 minute
    OnSuccess(func(data any) {
        ctx.Logger().Info("Job finished successfully", data)
    }).
    OnError(func(err error) {
        ctx.Logger().Error("Job failed permanently", err)
    }).
    Go()
```

## Graceful Job Termination

A key feature of Tako's Scheduler is its **Graceful Shutdown** mechanism. 

When a user exits the Tako application, the framework intercepts the shutdown sequence and cancels the master context of the Scheduler. Any currently running jobs will have their injected `context.Context` cancelled.

If you are writing a job that performs heavy I/O (like writing to a file or performing an HTTP request), always listen to the `jobCtx` to prevent zombie goroutines from hanging the application.

::caution
Always listen to `jobCtx.Done()` inside your long-running tasks. Failure to do so will cause the operation to continue running as a zombie process in the background, consuming CPU and memory even after the Tako application has shut down.
::

```go
ctx.Jobs().Dispatch(func(jobCtx context.Context) (any, error) {
    // Pass the jobCtx directly into your HTTP request
    req, _ := http.NewRequestWithContext(jobCtx, "GET", "https://api.example.com", nil)
    
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        // This will trigger immediately if the app shuts down during the request
        return nil, err
    }
    defer resp.Body.Close()
    return nil, nil
}).Go()
```
