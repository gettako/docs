In a traditional web backend or CLI script, debugging is as simple as dropping a `fmt.Println("debug info")` and watching the standard output. 

However, in a Terminal User Interface (TUI), printing raw text directly to stdout will disrupt your UI, causing text to overlap and breaking the layout.

Tako provides an asynchronous `contracts.Logger` that writes debug information to a rolling log file, bypassing the visual terminal screen.

::warning
**Avoid using Go's standard `fmt.Println` or `log.Fatal`.** Doing so will corrupt your Terminal UI, causing text to overlap. Always use `ctx.Logger()` to ensure safe background logging.
::

## Accessing the Logger

You can access the Logger instance from the IoC Container, or via the Application or Context API from anywhere in your codebase:

```go
app.Logger().Info("Application booted successfully")

// Inside a component's Init hook or an event listener
ctx.Logger().Warning("Failed to connect to the background worker")
```

## Log Levels

The Logger supports three standard severity levels, covering most standard use cases:

```go
// Informational messages for normal operation
ctx.Logger().Info("User %s authenticated", "username", username)

// Warnings for non-critical issues
ctx.Logger().Warn("Disk space is running low")

// Errors for critical failures
ctx.Logger().Error("Database connection dropped", "error", err)

// Fatal logs an error and shuts down the application (os.Exit(1))
ctx.Logger().Fatal("Critical boot failure, shutting down...")
```

## Structured Data (`With`)
Tako uses structured logging via standard `log/slog`. You can attach key-value pairs to subsequent log entries:

```go
authLogger := ctx.Logger().With("module", "auth", "session_id", 123)
authLogger.Info("User logged in") // Includes module=auth, session_id=123
authLogger.Warn("Invalid token")  // Includes module=auth, session_id=123
```

## Scoping (`Named`)
When building large applications, it is useful to categorize logs by their component so they can be easily filtered in tools like Datadog or ELK. Use `Named` to append a "logger" scope:

```go
dbLog := ctx.Logger().Named("database")
dbLog.Error("Connection refused") // {"level":"ERROR", "logger":"database", "msg":"Connection refused"}

apiLog := ctx.Logger().Named("api_gateway")
apiLog.Info("Request received") // {"level":"INFO", "logger":"api_gateway", "msg":"Request received"}
```

## Contextual Logging (`WithContext`)
In Go, it is standard practice to pass request-scoped data via `context.Context`. Tako's Logger supports extracting and embedding this data:

```go
ctxWithValue := context.WithValue(context.Background(), "request_id", "req-10293")

// Create a logger bound to this context
reqLog := app.Logger().WithContext(ctxWithValue)

reqLog.Info("Processing payment...") // Will capture context values automatically
```

## Where Are Logs Stored?

Because Tako operates in dual storage dimensions, your logs will be routed to different locations depending on how you compiled the application.

1. **Dev Mode (`go run`)**: `[Project Root]/.tako/storage/logs/tako.log`
2. **Production (Binary)**: `~/.app-name/storage/logs/tako.log`

If you are using Tako's Inspector CLI (`tako inspect`), you can stream these logs in real-time alongside your running application.
