When building terminal applications, developers often make the mistake of hardcoding hex colors like `lipgloss.Color("#FF5555")` directly into their component logic. 

While this works initially, it makes implementing a Light/Dark mode difficult and prevents your users from customizing their terminal experience.

Tako provides the `contracts.ThemeManager` to address this. It acts as a centralized registry for semantic color tokens.

## Accessing the Theme Manager

Like all core services, you can access the Theme Manager fluently via the Application or Context APIs:

```go
theme := ctx.Theme()
```

## Loading Themes via YAML

Tako provides a YAML loader to define themes without touching Go code. A theme file defines a *Theme Family* and multiple *Mode Variants* (like `dark` or `light`).

```yaml
# themes/dracula.yml
name: dracula

dark:
  brand:      "#bd93f9"
  bg:         "#282a36"
  text:       "#f8f8f2"
  components:
    button:
      bg:     "#44475a"

light:
  brand:      "#6272a4"
  bg:         "#f8f8f2"
  text:       "#282a36"
  components:
    button:
      bg:     "#e6e6e6"
```

## Automatic Loading & Cascade

By default, Tako automatically loads themes from the `"themes"` directory. It follows a **fallback hierarchy**, where the rightmost path has the strongest priority:

1. **Base Project** (`<project-root>/themes`): Your application's default themes.
2. **Dynamic Override** (`.tako/themes` or `~/.app-name/themes`): High-priority user theme overrides.

If a user creates a file with the same theme name in the dynamic override folder, Tako performs a **deep merge**. The user only needs to define the specific color variables they want to override, without copying the entire theme file.

```go
func (p *AppServiceProvider) Boot(app contracts.Application) error {
    // You do not need to call app.Theme().Load("themes") manually.
    
    // Default to the Dracula theme in Dark mode
    app.Theme().Use("dracula").Dark()
    
    return nil
}
```

## Custom Theme Directories

If you do not want to use the default `"themes"` directory, the framework allows you to define and load your own custom directories programmatically:

```go
func (p *AppServiceProvider) Boot(app contracts.Application) error {
    // Load themes from a custom directory
    app.Theme().Load(app.BasePath("my-custom-themes"))
    
    return nil
}
```

Tako uses **deep flattening** for YAML structures. For example, the `dark.components.button.bg` YAML value becomes available programmatically under the token name `"components.button.bg"`.

## Registering Themes Programmatically

If you prefer defining your themes in Go, you can register them programmatically using a 2-Dimensional model (Theme Family → Mode → Palette).

```go
app.Theme().Register("material", map[string]map[string]string{
    "dark": {
        "brand": "#bb86fc",
        "bg":    "#121212",
        "text":  "#ffffff",
    },
    "light": {
        "brand": "#6200ee",
        "bg":    "#ffffff",
        "text":  "#000000",
    },
})
```

## Accessing Colors in Components

When building your UI components, you should **never** hardcode colors. Instead, fetch them dynamically from the active theme using the `Get()` method:

```go
import "github.com/charmbracelet/lipgloss"

func (c *MyComponent) Render() string {
    // Get("brand", fallback...) fetches the color based on the ACTIVE theme and mode
    primaryColor := lipgloss.Color(c.ctx.Theme().Get("brand", "#ffffff"))
    
    style := lipgloss.NewStyle().
        Foreground(primaryColor).
        Bold(true)
        
    return style.Render("Hello, themed world!")
}
```

## Switching Themes & Modes Dynamically

Tako's `ThemeSelector` API uses a fluent builder to switch themes and modes interactively.

```go
func (c *SettingsComponent) Keys(km contracts.KeyManager) {
    // Switch the active color mode within the current theme family
    km.Bind("T", func() {
        if c.ctx.Theme().ActiveMode() == "dark" {
            c.ctx.Theme().Use(c.ctx.Theme().Active()).Light()
        } else {
            c.ctx.Theme().Use(c.ctx.Theme().Active()).Dark()
        }
        
        c.ctx.RenderNow()
    })
    
    // Switch to a completely different theme family (preserves the active mode)
    km.Bind("M", func() {
        c.ctx.Theme().Use("material") // If in dark mode, switches to material dark
        c.ctx.RenderNow()
    })
}
```

When you change the theme or mode, the Theme Manager automatically broadcasts a `theme:changed` event through the Event Bus. If you have components that cache their `lipgloss.Style` objects for performance, they can listen for this event and recalculate their styles.
