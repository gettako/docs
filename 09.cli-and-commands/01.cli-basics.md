While Tako is fantastic for building visual TUI applications, it is equally powerful for building standard, non-interactive Command Line Interface (CLI) tools. 

In fact, you can build an application that combines *both*. For example, running `my-app` might launch the TUI, while running `my-app make:user` might execute a background CLI script. 

## Writing a Command

To create a console command, you create a struct that implements the `contracts.Command` interface. This requires three methods: `Signature`, `Description`, and `Handle`.

```go
package commands

import "gettako.dev/tako/contracts"

type GreetCommand struct{}

func (c *GreetCommand) Signature() string {
	return "greet {name} {--s|shout : Print the greeting in uppercase}"
}

func (c *GreetCommand) Description() string {
	return "Greets a user by name."
}

func (c *GreetCommand) Handle(ctx contracts.CommandContext) error {
	name := ctx.Input().Argument("name")
	
	greeting := "Hello, " + name
	if ctx.Input().Option("shout") {
		greeting = "HELLO, " + name + "!!!"
	}

	ctx.Info(greeting)
	return nil
}
```

## The Signature Parser

Tako uses an incredibly expressive, Laravel-inspired "Signature" syntax to define command arguments and options. Instead of writing verbose struct tags or manually configuring flags, you simply write a human-readable string.

Here is a breakdown of the signature syntax:

* **Arguments**: Wrapped in curly braces `{name}`.
* **Optional Arguments**: Add a question mark `{name?}`.
* **Default Arguments**: Add an equals sign `{name=John}`.
* **Options (Flags)**: Prefix with two dashes `{--force}`.
* **Option Aliases**: Separate with a pipe `{--f|force}`.
* **Options with Values**: Add an equals sign `{--port=8080}`.
* **Descriptions**: Add a colon at the end `{--force : Force the operation to run}`.

You can mix and match these to create highly complex commands in a single line of text:
```go
// "make:model {name} {--m|migration : Create a migration file}"
```

## The Command Context

The `Handle` method receives a `contracts.CommandContext`. This context is your gateway to interacting with the console and the application.

### Console Output

Tako provides beautiful, pre-formatted output components right out of the box. You can call these directly on the context:

```go
func (c *GreetCommand) Handle(ctx contracts.CommandContext) error {
	ctx.Info("This is a blue informational message.")
	ctx.Warn("This is a yellow warning.")
	ctx.Error("This is a red error.")
	ctx.Done("This is a green success message.")
	
	ctx.Line("This is standard unformatted text.")
	return nil
}
```

### Accessing the Container

Because commands run within the Tako application lifecycle, you have full access to the Service Container. You can resolve database connections, loggers, or any other service you registered.

```go
db, err := contracts.Resolve[*sql.DB](ctx.Container(), "database")
```

## Registering Commands

To make your command available to the user, you must register it with the Console Kernel. You typically do this in your `main.go` file before running the application.

```go
func main() {
	app := tako.NewApp()

	// Register commands
	app.Commands().Register(&commands.GreetCommand{})

	tako.Run(app)
}
```

Now, from your terminal, you can execute the command:

```bash
go run main.go greet Alice
go run main.go greet Bob --shout
```

::tip
If you run `go run main.go` without any arguments, Tako will automatically launch the TUI Engine. If you want a pure CLI application without a TUI, you can tell the Console Kernel to set a specific command as the default using `app.Commands().SetDefaultCommand("your-command-name")`.
::
