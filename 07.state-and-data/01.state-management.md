In complex TUI applications, data often needs to be shared across multiple screens. For instance, you might need to access a user's session token or the current active UI theme from entirely different ends of your component tree.

Without a dedicated tool, developers usually resort to passing data down through deep layers of components ("prop-drilling") or creating global variables (`var GlobalTheme string`) that can lead to data races and panics. 

Tako addresses this by providing a thread-safe, reactive **State Manager**.

## The State Manager

The `contracts.StateManager` acts as an in-memory Key-Value store. It is accessible globally and safely via the Context API.

```go
state := ctx.State()
```

## Reading State

You can retrieve a value at any time using `Get()`. State keys return a `cast.Value` wrapper, allowing you to parse the underlying type without manual type assertions.

```go
// Retrieve a value and cast it as a string
theme := ctx.State().Get("user.theme", "dark").String()

if theme == "dark" {
    // Apply dark styling
}
```

If the value inside the state cannot be converted to a string, or if it doesn't exist, the `cast.Value` will return the fallback `"dark"`.

### Type-Safe Struct Binding

When storing complex objects or maps in State, you can extract them into Go struct pointers using `Bind()`:

```go
type Session struct {
    UserID string `json:"user_id"`
    Role   string `json:"role"`
}

var sess Session
err := ctx.State().Bind("active_session", &sess)
if err == nil {
    log.Println("Active user:", sess.UserID)
}
```

::note
Ensure your struct uses `json` tags (`json:"field_name"`) so that the unmarshaling process can match the generic state map to your struct fields.
::

## Mutating State Fluently

Tako provides a fluent syntax for updating state and notifying the rest of the application that a change occurred.

```go
ctx.State().
    Mutate("user.theme").
    Value("light").
    Broadcast()
```

### Breakdown of the Chain
1. `Mutate(key)`: Acquires a strict lock on the key to guarantee a thread-safe update.
2. `Value(val)`: Sets the new value in memory.
3. `Persist()` (Optional): Automatically mirrors the state to the persistent `KVStore` (`app.Storage()`) so it survives application restarts.
4. `Broadcast()`: Dispatches an internal event to all reactive observers.

::note
Calling `Broadcast()` automatically triggers a UI redraw (`RequestRender`), so you don't need to manually refresh the screen after mutating your state.
::

## Reactive Observers

The power of the State Manager lies in its reactivity. Any component or service can observe a specific state key and react when `Broadcast()` is called.

Let's make our `MainLayout` reactive whenever the user's theme changes. We attach the observer inside the component's `Init` hook to prevent memory leaks:

```go
func (l *MainLayout) Init(ctx contracts.Context) {
    // Listen for state changes
    ctx.State().Watch("user.theme").OnUpdate(func(oldVal, newVal any) {
        // You can safely cast newVal back using the cast package
        l.currentTheme = newVal.(string)
    }).Subscribe(ctx.StdCtx())
}
```

::tip
**Never** poll `Get()` inside a `Render()` loop. Observers guarantee that your UI updates only when the data changes, reducing CPU usage and eliminating screen flickering.
::

## Advanced State Concepts

### Computed / Derived State

Often, you want a piece of state to represent a calculation based on *other* state keys. Use `Compute()` to automatically re-evaluate a state value whenever any of its dependencies change.

```go
// "cart.total" automatically updates whenever items or discounts change
ctx.State().Compute("cart.total", []string{"cart.items", "cart.discount"}, func() any {
    items := ctx.State().Get("cart.items").Int()
    discount := ctx.State().Get("cart.discount").Int()
    return (items * 10) - discount
})
```

::warning
Computed functions must **never** contain side effects (like making network requests or mutating other states manually). They should be used strictly for pure data calculation.
::

### Wildcard Observers

Just like the Event Bus, the State Manager supports trailing wildcard (`*`) matching for observers. This is useful for capturing updates to a group of related fields.

```go
ctx.State().Watch("form.profile.*").OnUpdate(func(old, new any) {
    log.Println("A profile form field was modified!")
}).Subscribe(ctx.StdCtx())
```

::tip
Design a dot-separated namespace hierarchy (like `form.profile.name`). This makes wildcard observers efficient and your state architecture predictable.
::

### Loading Persisted State

If you previously saved a state value using `.Persist()`, you can initialize it back into memory when your component mounts using `LoadPersisted()`:

```go
// Will load from Storage if available, otherwise defaults to "light"
theme := ctx.State().LoadPersisted("user.theme", "light").String()
```

::caution
The `.Persist()` modifier stores data in plaintext on the local `KVStore`. **Do not** use this feature for highly sensitive information like passwords or authentication tokens. For sensitive data, use the `SetSecret()` method provided by the Storage API.
::

## State vs Storage

- Use the **State Manager** for ephemeral, fast-moving data that only needs to live while the application is actively running (e.g., active tabs, session tokens, UI toggles).
- Use the **Storage Manager** (covered next) for persistent data that must survive application restarts (e.g., user preferences, cached API responses). Use `.Persist()` if you want the best of both worlds.
