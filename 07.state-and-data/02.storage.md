While the State Manager is ideal for ephemeral runtime data, any information that needs to survive an application restart—like user preferences, offline sync queues, or authentication tokens—must be persisted to disk.

Figuring out where to save these files across different operating systems without polluting the user's root directory is often difficult. Tako's Storage system (`contracts.Storage`) solves this by providing a unified Key-Value interface that respects the Dual-Dimension path handling (Dev Mode vs Prod Mode).

## The Storage Manager

You can access the Storage Manager through the Application container or the Context API:

```go
storage := ctx.Storage()
```

## Basic Operations

The Storage Manager provides standard Key-Value operations using a Variadic API. Under the hood, Tako defaults to an embedded database (BoltDB) with auto-expiration (TTL) support.

### Writing Data (Set)

```go
// Store a simple string
err := ctx.Storage().Set("user.name", "Admin")

// Store complex JSON structures (auto-marshaled)
settings := UserSettings{DarkMode: true, AutoRefresh: false}
ctx.Storage().Set("user.settings", settings)
```

::tip
**Performance Tip:** If you are performing intensive writes and don't want to block the application's main thread (e.g., saving window positions on drag), use `SetAsync` for a fire-and-forget write.
```go
ctx.Storage().SetAsync("window.x", 1024)
```
::

### Reading Data (Variadic Get)

Tako's `Get` method is flexible. If you want a primitive value, it provides a fluent API. If you pass a pointer, it unmarshals complex structs automatically.

```go
// 1. Fluent Retrieval (Primitives)
theme := ctx.Storage().Get("user.theme", "dark").String()

// 2. Struct Unmarshaling (Complex Data)
var settings UserSettings
// If "user.settings" is not found, the struct remains unchanged
ctx.Storage().Get("user.settings", &settings)
```

::note
You can pre-fill your struct before calling `Get` to act as a fallback. If the data is missing from the database, your fallback values remain untouched.
::

### Time-To-Live (TTL) Expiration

You can persist data that will automatically delete itself after a certain period of time using `SetWithTTL`.

```go
// Data will be automatically purged after 24 hours
ctx.Storage().SetWithTTL("api_cache", responseData, 24 * time.Hour)
```

### Deleting Data

```go
ctx.Storage().Delete("user.name")
```

## Secure Storage

If you need to store sensitive information (like API tokens, OAuth keys, or passwords), writing them in plain text to a local database is a security risk. 

Tako supports encrypted storage adapters out of the box. Secure storage automatically encrypts your data using AES-GCM *before* it touches the physical file.

```go
// The encryption key is handled automatically by Tako
err := ctx.Storage().SetSecret("api_token", "secret_xyz123")

token := ctx.Storage().GetSecret("api_token").String()
```

::warning
**Never** store plain-text passwords or API keys using the standard `Set()`. Always use `SetSecret()` to ensure the data is encrypted at rest. This is critical since the `.tako/` folder might accidentally be exposed in dev environments if `.gitignore` is forgotten.
::

## Extending the Storage Manager

Tako's Storage relies on the **Manager Pattern**. This means it is extensible. If you want to use Redis, SQLite, or a custom cloud storage driver instead of the default local KV store, you simply `Extend` it:

```go
func (p *MyCustomProvider) Boot(app contracts.Application) error {
    // Register a custom driver named "redis"
    app.Storage().Extend("redis", func() contracts.Storage {
        return NewRedisStorageDriver()
    })

    return nil
}
```

Once extended, you can configure your application (`config/app.yml`) to use the new driver by default without changing component code.
