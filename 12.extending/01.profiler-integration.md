When you run `go run . inspect`, the DevTools dashboard shows FPS, average update time, and average view render time. These metrics don't appear by implicit behavior — your UI
adapter must report them. The official Bubble Tea adapter does this automatically. If you're building a custom adapter, you need two function calls in the right places.

## The API

```go [adapter.go]
func (b *BaseAdapter) RecordUpdate(dur time.Duration)
func (b *BaseAdapter) RecordView(dur time.Duration)
```

That's the entire profiler API for adapters.

## Where to Place Them

### RecordUpdate — After Input Processing

Wrap your input and event handling in a timer:

```go [adapter.go]
func (a *MyAdapter) handleInput(msg InputEvent) {
    start := time.Now()

    // Process the input — route keys, handle mouse, flush events
    a.HandleKey(msg.Key)
    a.FlushEvents()

    a.RecordUpdate(time.Since(start))
}
```

This measures how long your app takes to *react* to input — key routing, event handler execution, state mutations. High update times mean your handlers are doing too much
synchronous work.

### RecordView — After Rendering

Wrap your view rendering in a timer:

```go [adapter.go]
func (a *MyAdapter) render() string {
    start := time.Now()

    output := a.layout.View(a.Ctx, a.Router)

    a.RecordView(time.Since(start))
    return output
}
```

This measures how long it takes to produce a frame. High view times typically indicate expensive string concatenations or complex layout calculations.

## What Gets Calculated

From your `RecordUpdate` and `RecordView` calls, the profiler derives:

| Metric          | Calculation                                     |
|-----------------|-------------------------------------------------|
| FPS             | Number of `RecordView` calls per second         |
| Avg Update (ms) | Total update duration / update count per second |
| Avg View (ms)   | Total view duration / view count per second     |

These appear live in the `go run . inspect` dashboard under the Health panel. If no calls are made for 3 seconds, metrics automatically zero out (idle detection).

## Without BaseAdapter

If you're not embedding `BaseAdapter`, resolve the profiler manually from the container:

```go [adapter.go]
import "gettako.dev/tako/internal/debug/profiler"

var p *profiler.Profiler
ctx.Container().Make(&p)

p.RecordUpdate(dur)
p.RecordView(dur)
```

::tip
The profiler is only active in development mode. When it's nil (in production), `BaseAdapter.RecordUpdate` and `RecordView` are safe no-ops — no nil checks needed on your side.
::
